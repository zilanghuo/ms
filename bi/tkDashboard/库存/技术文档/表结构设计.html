库存模块 表结构设计

本文档按最新 库存检查看板-1.0.html 重新整理库存域表结构。ODS 表优先沿用 ms-warehouse-batch-data/ddl/inventory/ods 现有 DDL，并补充产品库存阀值设置接口组对应贴源表；非 ODS 旧表已从正文移除，并按最新页面重新设计 DIM / DWD / DWS / ADS 表。

库存检查看板是纯报表页面，前端接口最终只查询 ADS 层；DWD / DWS / DIM 仅作为 ADS 的建模上游，不直接服务页面查询。所有新表均属于库存域，命名遵循 dwd_inventory_*、dws_inventory_*、ads_inventory_*、dim_inventory_* 口径。
目录： 一、分层设计 ｜ 二、表清单 ｜ 三、ODS 贴源表 ｜ 四、DIM 维表 ｜ 五、DWD 明细表 ｜ 六、DWS 汇总表 ｜ 七、ADS 报表表 ｜ 八、发补货模块 ｜ 九、链路说明

一、分层设计

  • ODS：保留现有贴源表，承接 TikTok 在线商品、站点产品库存、FBT 库存、积加 PID 仓库库存、产品库存阀值设置接口组、可用仓库手工维护等来源。
  • DIM：维护仓库映射和库存阀值配置，属于库存域配置表，使用 _config 后缀。
  • DWD：沉淀 SKU 粒度库存检查明细快照，完成来源字段归一、仓库拆分、同步差异和异常判断。
  • DWS：从 SKU 明细聚合到 SPU 粒度，支撑 SPU 维度列表与合计。
  • ADS：面向报表接口查询，包含 PID&SKU 列表表、SPU 列表表、统计卡片表。

八、发补货模块表结构设计

本章节属于发补货模块，依据 ../发补货/需求文档.html 与 ../发补货/htmls/发补货看板-1.0.html 设计。页面最终采用 ADS 统计结果 + DIM 当前配置 查询机制：统计、加权、库存缺口、发货/补货决策等字段在 DWS/ADS 组装；生命周期、是否内容爆发、商务出单占比、剪辑出单占比、VOC 值等页面可编辑字段落在 DIM 配置表，修改后影响历史所有日期的报表展示。

8.1 建模原则

  • 模块归属：发补货模块，覆盖库存看板、备货模型、发货模型三个页面栏目。
  • 页面粒度：站点 + 店铺 + PID + 库存 SKU，列表不展示业务日期，但 ADS 保留 sdt 用于调度和历史查询。
  • 人工编辑：可编辑字段不写入 ADS 统计表，统一维护在 dim_inventory_replenishment_sku_edit_config 当前生效配置表。
  • 报表查询：接口查询 ads.ads_inventory_replenishment_dashboard_1d 后，按 site_code, store_name, pid, inventory_sku 左关联 DIM 配置表。
  • 加权计算：S7、S30、S7/S30、动态权重档位、加权日均等在 DWS 层计算；ADS 层承接备货与发货模型的最终基础结果。
  • 人工覆盖：最终展示生命周期、VOC 等字段按 COALESCE(dim.人工配置, ads.系统计算) 输出；受人工配置影响的目标库存、安全库存、是否备货、是否发货等建议字段建议在接口 SQL 的 ADS + DIM 查询 CTE 中实时重算，避免配置修改后历史 ADS 宽表失效。

8.9 报表 ADS + DIM 查询口径

发补货报表查询不直接修改 ADS 表。接口查询建议使用如下逻辑：先过滤 ADS 业务日期和页面条件，再左关联当前配置 DIM，并用人工配置覆盖系统字段。

展示字段类型来源建议说明
商品基础信息、库存看板字段ads_inventory_replenishment_dashboard_1d站点、店铺、SPU、PID、MSKU、库存 SKU、库存汇总、国内/海外仓库存。
动态加权字段ads_inventory_replenishment_dashboard_1dS7、S30、S7/S30、动态权重档位、加权日均在 DWS/ADS 计算。
页面可编辑字段dim_inventory_replenishment_sku_edit_config生命周期覆盖、是否内容爆发、商务出单占比、剪辑出单占比、VOC 值、运输方式覆盖、备注。
最终建议字段ADS + DIM 查询 CTE目标库存、安全库存、是否备货、是否发货、运输方式等受人工覆盖影响的字段，应在查询层按最新 DIM 配置实时计算。
关联键说明风险控制
a.site_code = c.site_code站点一致配置表主键必须保证唯一，避免 JOIN 放大
a.store_name = c.store_name店铺一致如后续有店铺 ID，应优先使用店铺 ID
a.pid = c.pidPID 一致需求文档提示 PID 非唯一，因此不能单独用 PID 关联
a.inventory_sku = c.inventory_sku库存 SKU 一致页面编辑提示按库存 SKU 维度落库，但正式实现建议加站点、店铺、PID 共同约束
SELECT
    a.sdt,
    a.site_code,
    a.store_name,
    a.pid,
    a.inventory_sku,
    a.weighted_daily_sales_qty,
    COALESCE(c.lifecycle_stage_override, a.system_lifecycle_stage) AS final_lifecycle_stage,
    COALESCE(c.voc_value_override, a.system_voc_value) AS final_voc_value,
    c.is_content_burst,
    c.business_order_ratio,
    c.clip_order_ratio
FROM ads.ads_inventory_replenishment_dashboard_1d a
LEFT JOIN dim.dim_inventory_replenishment_sku_edit_config c
    ON a.site_code = c.site_code
   AND a.store_name = c.store_name
   AND a.pid = c.pid
   AND a.inventory_sku = c.inventory_sku
WHERE a.sdt = '${bizDate}';

8.10 发补货模块链路说明

  • ods_inventory_tiktok_product_online_product_df 提供商品基础信息，是库存看板、备货模型、发货模型的共同维度来源。
  • ods_inventory_tiktok_site_product_stock_df 与 ods_inventory_tiktok_fbt_stock_df 汇入 dwd_inventory_replenishment_sku_stock_df，形成 SKU 粒度库存归一明细。
  • ods_inventory_multi_platform_sales_performance_df 汇入 dwd_inventory_replenishment_sku_sales_1d，用于后续窗口统计。
  • dws_inventory_replenishment_sku_model_1d 统一计算总库存、总在途、总可用、S7、S30、动态权重、加权日均、系统生命周期和 SKU 分层。
  • ads_inventory_replenishment_dashboard_1d 承接发补货页面三个栏目所需的基础统计结果和系统建议字段。
  • dim_inventory_replenishment_sku_edit_config 仅保存当前生效人工编辑字段；由于业务要求“修改影响历史所有日期”，该表不做日快照，不参与 ADS 回刷。

九、链路说明
