四、异常 CASE 逻辑

ADS SKU 和 DWS SPU 使用同向异常逻辑。DWS SPU 是汇总后重算，ADS SKU 是明细行重算。

优先级 代码值 判断条件 中文名 / 提示文案
1 store_stock_jijia_no_stock COALESCE(should_sync_inventory_qty, 0) = 0 且 COALESCE(store_synced_total_qty, 0) > 0 店铺有库存，积加无库存；检查是否手动填写库存。
2 oversold_risk exception_store_backend_should_sync_total_diff_qty > COALESCE(inventory_threshold_qty, 0) 超卖风险；实际没那么多库存，可能超卖，立即检查。
3 threshold exception_store_backend_should_sync_total_diff_qty > 0 且 <= COALESCE(inventory_threshold_qty, 0) 阀值问题；库存到达阀值，调整阀值或备货。
4 less_sync COALESCE(should_sync_inventory_qty, 0) > 0 且 exception_store_backend_should_sync_total_diff_qty < 0 少同步；库存同步数量少了，安排检查库存。
5 normal 不满足以上异常条件。 正常。
字段方向： 库存总差异 = 店铺侧被同步 - 应该被同步。因此差异为正代表店铺侧挂得偏多，超过阀值就是超卖风险；差异为负代表店铺侧挂得偏少，属于少同步。

五、SPU 聚合计算口径

SPU 表不是简单按 PID 行汇总。由于一个库存 SKU 可能挂在同一个 SPU 下的多个 PID，如果直接汇总会放大库存，因此 DWS SPU 会先去重再汇总。

步骤 关键键 逻辑 结果
1. 来源过滤 smt、sdt 读取 dwd.dwd_inventory_stock_check_sku_snapshot_1d 当前业务分区。 取得 SKU 明细快照。
2. SKU 去重 store_name + spu + COALESCE(msku, inventory_sku, sku_id) 同一库存 SKU 在同店铺同 SPU 下只保留一份库存值，各字段按 MAX、SUM 或拼接规则归并。 避免 PID 展示行重复累计库存。
3. SPU 汇总 store_name + spu 对去重后的 SKU 进行库存、同步量、差异量汇总；占比类字段按 SPU 汇总后的分子分母重算。 得到 SPU 列表数据。
4. 异常重算 汇总后的差异与阀值 使用 SPU 汇总后的 exception_store_backend_should_sync_total_diff_qty 和 inventory_threshold_qty 重新打标。 SPU 异常方向与 SKU 一致。

八、已固化的修正口径

  • 库存总差异方向固定为 店铺侧被同步 - 应该被同步，差异为正才可能进入阀值问题或超卖风险。
  • 英国退货仓差异公式为店铺侧英国退货仓减积加英国退货仓，不再扣减 FBT 可用量。
  • 英国退货仓差异不纳入库存总差异，只参与异常仓库定位展示。
  • 库存阀值按同店铺 + 同库存 SKU 取最大值，保证跨 PID 展示一致。
  • 店铺侧各仓同步库存按同店铺 + 同库存 SKU 收敛，PID 只是展示层级。
  • 异常仓库按各仓差异不为 0 拼接；SPU 层按去重 SKU 后的仓差异归并。
