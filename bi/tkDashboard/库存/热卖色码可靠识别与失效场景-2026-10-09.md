# 热卖色码可靠识别与失效场景

日期：2026-10-09。状态：业务规则建议，未改系统。本次未重新拉销售或库存，使用本会话2026-10-06校准及2026-10-09 W0575核对结果作案例，不将历史统计冒充今日重新查询结果。

## 核心判断

前三颜色×各色前三码适合作为固定容量的关注清单，不能单独代表全部真实主销。判断补货需要的是正常可售及可比经营条件下可持续的需求；实际销量还受供给、可购买状态、流量、价格和活动影响。供给长期缺失时真实需求不可直接观测，没有一个仅靠销售报表的公式能保证还原。

建议采用：原始销量排名 + 可售状态/时长 + 可比条件下的销售速度 + 历史主销保护 + 近期趋势 + 数据置信状态。标签数量不固定，显示前三可以保留，但不得漏掉额外主销或历史断货主销。

## 方法比较

| 方法 | 优点 | 适用和限制 |
|---|---|---|
| 近30日销售排名 | 简单、可复算 | 供给和经营条件相近时适合作基础；否则只反映已实现成交 |
| 可售时长校正 | 减少长期没货造成的低估 | 用同一可售窗口销量/有效可售时长；必须包括有货零成交日。活动、价格和流量仍可能不同，不能直接当真实需求 |
| 可比经营窗口比较 | 对颜色/尺码偏好更有解释力 | 优先共同正常可售的日期、相近价格/活动/履约条件；观察窗口少则降低可信度。不能将不同季节日期简单等价 |
| 供给与经营因素共同建模 | 可估计缺货损失及需求区间 | 要有较长历史、库存轨迹和经营变量，并做时间外验证；模型仍有不确定性，不建议当前直接堆复杂模型 |

示例仅说明计算，不是实际数据：某色10个可售日售100件，另一色30个可售日售150件；在经营条件接近前提下，日均10与5比总量100与150更能解释销售速度。若前者10天全是大促，则不能据此判为两倍自然需求。缺货时段零成交不能补成零需求；剔除断货后剩余有货时段也可能不是随机样本。

## 推荐分步规则

1. 固定站点+店铺+SPU范围、业务时区、颜色/尺码映射和订单件数口径，正常订单、测试/寄样、取消等分清；退款率独立观察，不将后期退款随意倒扣到不同销售日。
2. 保存SKU每日或更细的可售状态：仓库可用、店铺已同步、对应地区实际可购买、上下架和履约方式。采购在途不等于可售；日末库存不能完整反映日内断货。
3. 用近30日原始销量展示成交结构；在可比条件和可售窗口下计算销售速度作校正参照。7/14日作趋势提示，不作为一票否决；不能只用正销量日作分母。
4. 先按款内颜色结构识别主销，再分析各颜色内部尺码结构；款级尺码分布只能作为参考，颜色差异、面料版型与尺码映射需保留。重要码断货会压低整色销量，不能把该色认作低需求。
5. 分层允许多主销、均衡、边界待核，不强制每款只有三色三码。参数或窗口轻微变化就变档的色码暂不自动降级，保留版本和原因。
6. 历史主销+断货证据进入独立保护名单，可超过当前关注名额。补货后的14个完整可售日只作初始候选观察期，不构成充分置信保证；还需样本量、正常经营、季节和趋势。
7. 新色/新品、长期断货无历史、低样本或数据缺失：显示待观察/待核实，不强制认定普通色码。可以参照同版型历史款，但必须标记为参考，不冒充本款已验证结果。
8. 若关键色码能安排在相同价格、较完整库存及类似流量条件下观察，则用新数据校准；不要为了识别而自动补货、调价或投广告，需要另行经营决策。

## 失效场景及处理

| 场景 | 可能误判 | 应对 |
|---|---|---|
| 长期断货 | 原主销销量归零被移出 | 历史主销保护；有库存轨迹才做校正；无历史标待核 |
| 颜色只剩边缘码 | 整色被低估 | 检查该色主力尺码可售情况，颜色与尺码两层校验 |
| 仓库有货但店铺同步为0/下架/地区不可配送 | 把无法购买误判为无需求 | 按渠道实际可售状态；不要只看仓库数量 |
| 新色、刚补货、上架时间短 | 30日累计销量低 | 记录起售/恢复时间，参考同期正常可售表现，标新晋待观察 |
| 投放和内容只推某色 | 曝光优势被当作普遍偏好 | 区分有支持的销售与常态需求；仅在真实有色码级曝光时算色码转化，不能均摊PID曝光伪造 |
| 直播拍卖、折扣、清仓、优惠券或不同价格 | 活动高销量被外推成常态需求 | 单列活动/价格期；活动真实需求可以管理，但结束后不直接按活动速度备货 |
| 履约差异，如海外仓转国内直发 | 时效影响转化被误判颜色不受欢迎 | 比较相同地区和配送条件，记录切换时间 |
| 缺货替代购买 | 次选颜色暂时销量升高 | 对照主销缺货期与恢复期；没有用户级证据不直接断言替代量 |
| 季节、热点、素材热度衰减 | 老主销永久保留，或短期热点被长期外推 | 多窗口趋势及季节复核，历史保护有复核而非永久不变 |
| 低销量、并列、边界接近 | 多一两件就改标签 | 允许均衡和低置信、保持边界稳定，结合样本量而非仅天数 |
| 多PID、共用SKU、映射错误、组合装 | 重复销量/库存或错误颜色归属 | 可加总销售分组与共享库存分开；核对标准库存SKU、颜色ID、尺码和组合换算 |
| 数据延迟、当天未完、漏页或库存快照过旧 | 虚假下滑、虚假断货 | 完整业务日、分页和汇总对账、数据截止/更新时间明确 |
| 高退货、高取消、尺码问题 | 成交热度被当成值得继续放量 | 保留成交热度，同时单列有效履约、成熟退货批次与质量风险，不混为一个标签 |
| 仅观察一个店铺/站点或变更版型批次 | 将局部结构套全站或旧结构套新版 | 独立计算范围及版本，有证据后再合并 |

以上是可能导致判断失效的机制，不代表本次样例已发生全部情况。

## 结合此前案例

- W0575当次库存快照：墨绿M/L、赭黑M/L可用库存0；赭黑XL有国内1件但店铺已同步0。因此仅按后续成交排名会有漏掉原主销的风险。库存检查标记正常并不能证明有货。
- W0180校准窗口内巧克力前10天没有成交，但未验证是否断货、新色或其他原因，不能把首次成交日期直接当上架日期。
- W5558用户确认黑色为次热卖，即使整款贡献超过10%；说明全局固定占比不能替代款内相对层次。
- W0169存在六个接近的头部颜色，前三只表示展示/关注名额；W0181尺码25～34件，缺乏强行拆档依据。

## IT优先补的数据

最小可用字段：店铺/站点/SPU/PID/标准SKU/颜色/尺码、日期或时间段、销售件数、可售库存和店铺同步数量、上下架/可购买状态、商品价格及活动、履约仓/方式、热卖历史和手工确认记录、数据更新时间。若能取得真实流量及投放/内容支持记录，可提升解释性；不要因为暂缺流量而伪造SKU级分摊。

第一阶段先建立历史可售与标签快照、数据对账、缺货保护和异常提示；第二阶段用可比窗口、跨款人工样例及未来时间窗口验证参数。关注历史主销漏判、明显次销误升、名单抖动及可售恢复后的表现，不能只检验是否复现训练案例。
