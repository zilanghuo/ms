TikTok Shop / 订单判定方案

联盟达人单、商家达人单、普通单判定方案

目标是为业务系统沉淀一套可执行、可回溯、可扩展的订单来源分类口径，输出 NORMAL、ALLIANCE_CREATOR、MERCHANT_CREATOR 三类结果，并列出对应 TikTok Shop 官方 API 能力。

普通订单接口不能直接判断达人归因 联盟订单接口是达人单判定主依据 商家达人单通常是业务派生口径

一、核心结论

不要只依赖普通订单接口判断达人来源。

普通订单详情通常只覆盖支付、履约、收件人、商品明细等信息，缺少达人归因、联盟活动、佣金来源等关键字段。

  1. 先用普通订单接口拿全量订单底表。
  2. 再用联盟订单接口判断是否为达人单。
  3. 对已识别的达人单，再结合达人合作活动 / campaign 信息细分为商家达人单或联盟达人单。
  4. 最后在业务系统中沉淀统一分类字段，而不是直接信任单一接口原始返回。

二、推荐分类口径

1. 普通单

  • 订单存在于普通订单表。
  • 订单不存在于 Search Seller Affiliate Orders 结果中。
  • 输出：order_source_type = NORMAL

2. 联盟达人单

  • 订单命中 Search Seller Affiliate Orders。
  • 但无法证明其属于商家自建/定向合作活动。
  • 输出：order_source_type = ALLIANCE_CREATOR

3. 商家达人单

  • 订单命中 Search Seller Affiliate Orders。
  • 且能关联到商家自己的 Affiliate Partner Campaign 或活动商品清单。
  • 输出：order_source_type = MERCHANT_CREATOR

三、推荐判定流程

Step 1: 普通订单接口
  -> 拉取订单列表 / 订单详情
  -> 形成订单底表（全量）

Step 2: 联盟订单接口
  -> Search Seller Affiliate Orders
  -> 按 order_id 或 line_item_id 做关联
  -> 命中则先标记为达人单

Step 3: 达人合作活动接口
  -> Get Affiliate Partner Campaign Detail
  -> Get Affiliate Partner Campaign Product List
  -> 判断订单商品 / 订单归因是否属于商家合作计划

Step 4: 输出业务分类
  -> NORMAL
  -> ALLIANCE_CREATOR
  -> MERCHANT_CREATOR

推荐以 order_id 为主关联键；如果联盟侧或活动侧返回的是更细粒度数据，再补充使用 line_item_id / sku_id / product_id 作为辅助关联条件。

四、为什么订单详情不够

字段类型 能否直接判达人归因 说明
order_type 不能 这是订单业务类型，不是达人来源类型。
is_sample_order 不能 最多说明是否样品单，不能区分联盟达人单或商家达人单。
seller_sku / product_id 不能 只是商品维度信息，不是归因维度。
支付 / 履约字段 不能 仅描述订单状态、支付状态、物流状态。

六、最终判定规则

规则 1：普通单

if order in normal_orders
  and order not in seller_affiliate_orders
then NORMAL

规则 2：联盟达人单

if order in seller_affiliate_orders
  and order not linked to merchant partner campaign
then ALLIANCE_CREATOR

规则 3：商家达人单

if order in seller_affiliate_orders
  and order linked to merchant partner campaign
then MERCHANT_CREATOR

七、系统字段建议

  • is_affiliate_order：0 / 1
  • order_source_type：NORMAL / ALLIANCE_CREATOR / MERCHANT_CREATOR
  • affiliate_campaign_id
  • affiliate_campaign_type
  • affiliate_creator_id
  • affiliate_creator_name
  • affiliate_match_source：seller_affiliate_orders / partner_campaign_mapping / manual_rule
  • affiliate_match_confidence：HIGH / MEDIUM / LOW

不建议只存一个中文标签。保留来源、证据、置信度，后续复盘和排查会容易很多。

八、落地建议

阶段一：先做稳定版

  • 落普通订单底表
  • 接入 Search Seller Affiliate Orders
  • 先输出 普通单 / 达人单

阶段二：再细分达人单

  • 补接 Get Affiliate Partner Campaign Detail
  • 补接 Get Affiliate Partner Campaign Product List
  • 再输出 联盟达人单 / 商家达人单

当前最稳的现实结论：

官方公开能力中，能确认存在“联盟订单查询”API；但“商家达人单”通常不是一个单独公开 API 直接返回的原生类型， 更适合作为你们业务系统在订单 + 联盟订单 + 活动关系三层数据之上派生出来的分类结果。
