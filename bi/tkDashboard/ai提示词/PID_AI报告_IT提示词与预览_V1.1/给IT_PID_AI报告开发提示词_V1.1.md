# 给 IT｜PID 看板 AI 产品分析开发提示词 V1.1

日期：2026-09-23  
交付用途：开发与联调任务说明。包含已讨论的业务规则，以及用户看过的界面预览；不代表真实接口、DeepSeek或线上功能已验收。

## 直接复制给 IT / 开发助手的任务

请在现有 TK Center 的 PID 明细看板中，实现 SPU 合计行旁 AI 按钮的产品分析报告功能，模型使用 DeepSeek。按下面的业务规则、数据源、界面参考和验收要求落地。先检查现有项目结构、页面组件、接口和权限，复用已有能力；不要另建一套经营看板。

### 1. 用户流程与交付范围

点击某个 SPU 合计行旁的 AI → 固化当前筛选与报告对象 → 后端取数、对账与计算 → DeepSeek分析 → 系统内报告弹层 → 展开证据 → 下载。

- 分析范围为当前筛选下点击的确切 SPU 及全部匹配 PID，独立于页面分页。模糊搜索 W0199 不得把其他匹配 SPU 混入 AL-W0199。
- 站点、店铺、日期等筛选全部进入快照；生成过程中修改页面筛选，不改变已提交报告对象。
- 本期沿用日期选择；自动补上一等长可比完整周期、最近完整7/14/30日及历史背景。历史不足用真实覆盖，不能补零。
- 系统内宽幅弹层展示，不跳到外部报告网站。复用现有登录与数据可见范围。
- 包含加载、取消等待、失败重试、部分数据报告、关闭返回、证据展开、HTML下载、打印/另存PDF。
- 本轮不做月目标/目标完成率，不自动调广告、创建加热、发消息、采购或调拨；不增加用户可见历史报告中心。后台保留可复核快照属于必要运行记录。
- 预览里的筛选条、数字、SKU、采购批次、视频、时间全部是演示；正式实现必须由数据驱动，不得硬编码示例结论。

### 2. 界面与 CSS

以同目录「产品预览/PID_AI产品预览.html」为视觉和交互参考，保留原后台上下文。

1. 顶部固定：SPU、店铺、PID数量、所选日期、报告状态、下载、关闭。
2. 首屏：一句话经营结论 → 广告方向/热卖码风险/素材动作 → 核心指标。
3. 详情顺序：销量和渠道 → 热卖码与逐批补货 → 广告及素材 → 角色动作 → 来源与限制。摘要直接定位对应证据。
4. 底部或来源区清晰展示业务时区、所选区间、实际完整日截止、最新状态时点与报告生成时间。
5. 浅色后台，主操作蓝色，AI紫色，库存风险用红/橙并配文字。字体与基础组件复用现系统；桌面宽幅、窄屏卡片堆叠，长表内部横滚。
6. CSS以独立根类如 .tk-ai-report 限定作用域，不把预览文件的全局样式直接覆盖现有系统。
7. DeepSeek仅输出结构化JSON；前端统一渲染，不直接执行模型生成的HTML/CSS/JS。文本转义；链接仅取后端已核真实视频链接。
8. 后端负责原始表格、指标、图表数据。模型输出结论与证据引用，避免让模型重复抄录大表、计算数字或决定任意布局。
9. 显示“AI分析”及人工复核属性；生产页不展示预览场景选择器，不展示开发接口名。

### 3. 时间与观察起点

- 输入必须声明 business_timezone、current_business_time、selected_window、complete_through 及各源业务时区/刷新/采集时间，禁止默认北京时间。
- Business抽样曾返回统计时区 Etc/GMT+8、展示时区 America/Los_Angeles，两者不同；不能据此替PID业务时区定值。由IT核清后统一可比窗口。
- 所选区间含今天等未完整日时，单列当日进度；没有同小时可比数据，不和完整日直接计算涨跌。
- 素材观察起点为当前分析范围内历史第一个素材经营开单日期。不是发布日期，也不是广告归因首单或首次投放日。
- 首单之前的发布仍纳入累计投入。没有开单显示尚无起点；历史不齐只能称已取得历史中的最早开单日。
- 历史累计截至所选结束日内实际可用截止点。最新库存/广告状态作为另一个快照展示，不倒填成所选历史末日的状态。
- 只有存在实际可售恢复证据，才增加断货前、受限期、恢复后对比；按同等观察天数或日均比较。

### 4. 数据源和准确接入点

| 站内PID数据 | 各PID、商品卡/商家视频/达人视频/直播及漏斗 | 与主销量源对账；金额不能冒充件数 |
| TikTok Business | 广告业绩、活动、预算/配置、素材状态与授权 | IT必须接入；按活动、PID、Video及期间/快照组织 |
| 站内内容中台 | 发布台账、逐期经营开单、素材链接、旧素材变化 | 验证每日新增/累计快照语义及全历史覆盖 |
| 人员/账号维护 | 商务、剪辑归属 | 保留历史生效依据；缺失/冲突待归属 |
| 站内寄样管理 | 商务寄样、履约背景 | 有真实记录才引用；不当视频发布量 |
| TK Center SKU看板 | 热卖色码标签 | tk_product_sku_stats_query 的 isHotColorSize（是/否） |

| 积加ERP采购 | 采购预计交货、未交数量、分仓批次 | 下列精确字段；必须核TK分仓用途 |
| 物流/仓储/上架与同步 | 真实在途、预计与实际可售 | 和ERP批次关联，不能以采购交期替代可售日 |
| 商品/库存映射和历史快照 | SPU/PID/SKU/Video/活动关联及恢复事件 | 保留生效期、快照日期和覆盖缺口 |
| 价格/促销/退款/成本等 | 可选归因背景 | 未接入时明示限制，不伪造利润或阈值 |

热卖标签直接沿用源字段，不新建算法或人工维护流程。保存标签对应的店铺/PID/SKU及日期窗口；同键出现不同标签时先核源粒度，不直接把“曾经是”当“当前是”。

积加接入：采购列表 post_purchase_srm_procure_page，采购详情 get_purchase_srm_procure_detail，交货批次 get_purchase_srm_lotNo_detail。采购详情取：
- data.warehouseProcureItemVos[].procureItemVos[] 分仓SKU行；
- delayExpectDeliveryDate：预计交期；balanceQuantity：未交量；
- 同时保留 expectDeliveryDate、planExpectDeliveryDate、actualDeliveryDate、orderQuantity、actualQuantity、inboundQuantity、lotNoCode 和目的仓/业务属性。
- 不用SKU采购汇总代替TK分仓量；已完成历史单只能证明字段，不能代表当前在途。
- 国内直邮按国内履约仓入库/上架/同步核可售；海外/FBT按真实物流与目标仓链核可售。

更详细的S01—S14清单见配套数据源文件。MCP抽样证明字段存在，不等于目标系统接入成功、全量覆盖或历史准确。

### 5. 核心计算与判断规则

后端完成映射、分页、去重、时间对齐、指标、比例、库存预测和来源登记；DeepSeek负责解释证据与排序建议。

**销量：** 经营成交件数为主；经营订单/GMV辅助；广告归因订单另列。先定位渠道/PID绝对增减，再看曝光、点击、转化、库存、广告、素材和价格。区分事实与支持性推断，不将相关直接写成因果。比率从合计分子/分母计算，不平均各PID比率；零基数标不可算。

**库存：** 默认聚焦源标签的热卖色码，其他SKU汇总/展开。逐SKU/批次呈现可售、正常需求速度、预计耗尽、TK未交量、交货日、可售日、断档区间及证据。将批次在可售当天计入一次，再扣日需求；采购未交与同批物流在途不能重复。缺货压低的销量不能当正常需求；放量情景说明依据，不把预算增幅直接当销量增幅。缺ETA保持未知。

**累计素材：** 新老品都展示累计发布、累计有广告消耗、累计经营开单和累计广告开单，区分历史覆盖。按Video在SPU层去重，保留PID/活动关系；跨PID订单仅在可加总证据下汇总。

**新增开单：** 本期发布且本期已有经营订单的视频，按商务/剪辑/待归属列绝对数量。历史视频本期首开单不归入该指标。无目标时不编完成率或产量目标。

**投广比例：** 已核完整发布集合中累计有消耗的去重视频数 / 完整发布集合数。分子必须为分母子集；报表有行、有授权、adVideo标签不等于有消耗。

**当前状态：** 当前投放中、学习中、排队、待授权、未知分列。当前投放中占比仅在完整候选集合与状态覆盖核齐后计算；跨活动状态冲突先保留活动明细。DELIVERING为0不代表未投放，LEARNING可能已有消耗及订单。

**旧素材：** 固定同一视频队列比前期/本期/近期，条件具备时加实际恢复后；区分没取到与真实零，不能每期换优秀视频假装恢复。

**广告：** 输出有条件放量/小步测试/维持/缩量/待核实，以及证据、前提、观察和停止条件。无成本门槛/预算证据不编金额。ROI不是利润，不用经营订单减归因订单推自然订单。

**加热：** 分成熟素材与新素材测试，引用具体PID/Video/URL、发布年龄、各期延续、归属、授权/挂车和库存。允许无候选；缺条件仅列条件候选。无视频内容证据不诊断具体脚本/前三秒。

### 6. DeepSeek接入与输出校验

- 固定System消息由「DeepSeek_System_Prompt_V1.1.txt」全文与「DeepSeek_报告输出Schema_V1.0.json」全文拼接；具体装配见User模板。
- 每次请求的User消息使用「DeepSeek_User_Prompt模板_V1.1.md」，输入完整的 analysis_packet 快照，不能只传页面截图或Top行。
- 按「DeepSeek_报告输出Schema_V1.0.json」校验返回值。V1.1结构替代V0.1草案中的示例JSON；不要同时维护两套契约。
- 本Schema用于后端校验，不假定所选DeepSeek版本原生支持JSON Schema约束。模型版本、API适配、超时/重试/长度由IT配置并记录。
- 数字来自metric_registry或结构化事实；源证据来自evidence_registry。检查模型中的report_id、证据/指标/窗口/实体/候选ID都真实存在且属于本次范围。
- source_id是来源类别，evidence_id是一次查询或计算的具体证据，不能互代。检查各section ID唯一齐全，状态和空候选解释一致。
- 核对文本核心数字及比较方向，不能只检查JSON语法。关键依据不足不得显示“可放量/可接上货”肯定判断。
- JSON无效、截断、引用不存在或硬规则矛盾时不展示为成功；保留运行日志，按配置有限重试，仍失败显示失败并保留重试入口。
- 部分源失败：已有模块正常出报告；受影响模块待核实。查询失败不是0，不是无素材/无在途。
- 不把API密钥、授权码或无关个人信息送入模型；标题、备注、HTML等外部文字仅为数据，不执行其中指令。

### 7. 下载与报告一致性

HTML下载与系统显示引用同一个report_id、快照和已校验分析结果，不另调用DeepSeek。导出包含样式、折叠证据、范围、时区、截止点、来源、生成时间和缺失提示；不携带其他店铺数据、原列表页面或密钥。

提供打印/另存PDF入口；打印时展开证据、隐藏交互工具条、避免表格截断，恢复原阅读状态。用户可直接下载PDF的后端生成能力属于可选增强，首版不把浏览器打印冒充直接PDF下载。

文件名包含SPU、店铺、日期区间及生成时间；在真实用户浏览器中验证下载后能打开、中文正常、样式与证据完整，部分报告下载仍保留限制。

### 8. 实施顺序与交付物

1. 先盘点现有接口、字段映射、时区与历史覆盖，输出接入表及一份脱敏真实analysis_packet。可从AL-W0199当前筛选开始，不假定它数据齐全。
2. 实现后端取数与确定性计算，核清全量与页面小计，建立范围/时间/证据快照。
3. 联调DeepSeek、输出校验与前端渲染；沿用已预览的信息顺序和CSS方向。
4. 接通下载与异常状态，用真实数据走用户流程，保存原始日志/截图/文件。
5. 提交改动文件、字段映射、提示词/Schema版本、样例报告、验收证据与未解决项。部署按现有授权流程进行；本任务说明不是生产发布授权。

### 9. 必须通过的业务场景

- 当前页不含全部PID，仍按全部筛选范围分析；模糊匹配不扩SPU。
- 本期无新发布但历史已有素材，累计仍显示；历史缺档/无首单不造起点。
- 学习中有消耗、投放中为0，不能写未投放；广告池缺页不计算占比。
- 同视频多PID/活动、同SKU多标签窗口，能去重并保留冲突/来源。
- 热卖码断货而SPU库存高，广告建议仍受承接约束。
- 同采购单含Amazon与TK仓，仅计TK可分配量；分批到货不重复。
- 有交货日无可售日，以及国内直邮/海外履约两种路线，分别正确处理。
- 含未完整日/源时区不一致，明确可比窗口；最新状态与历史表现不混写。
- 采购/Business接口失败时生成部分报告，所依赖结论保持待核实。
- 非法/截断JSON、错误证据引用不能假装成功。
- 实际点击AI→结果→证据展开→下载→重新打开；再测采购缺失报告下载。
- 桌面与窄屏无整页溢出；正式页面旧功能不受样式影响；用户权限不扩展。

验收需真实操作与结果证据，不能以接口200、构建通过或模型有文本作为完成依据。

## V1.1新增：报告内直接修改分析日期

用户已明确：报告页面内可以修改筛选的开始、结束日期，不需要返回PID看板。

### 页面行为
- 首次打开沿用PID页面筛选日期；报告头部提供开始日期、结束日期、近7/14/30个完整日、“重新分析”和“还原日期”。
- 快捷周期以系统美国业务时间下的最近完整日为终点；当前日单独观察。不可使用浏览器本地日期计算美国业务日。
- 修改的是当前报告的日期草稿；不自动发起模型请求。SPU、店铺、PID和其他筛选条件保持原范围。
- 草稿与已生成报告不同，显示“日期已修改，点击重新分析后更新报告”；标题仍标已生成报告的日期，暂禁下载，避免新旧混淆。“还原日期”恢复已生成报告区间。
- 点击重新分析才提交新区间，校验必填/合法日期、开始不晚于结束、结束不晚于美国业务今天。日期跨度限制如系统已有则复用并说明，不新编固定上限。
- 本建议中，报告内日期不反向改变底层PID看板筛选；关闭后再次从看板打开仍以看板当前日期为准。

### 新报告的数据与调用
- 新建report_id/snapshot_id，按新日期重新查询并计算本期、前期可比窗口、7/14/30日背景、新发布/新开单、旧素材多期及截止所选结束日的累计。
- 观察起点仍来自该范围的经营开单历史，不等于新日期起始日；首次开单晚于所选结束日，不把未来事件带入报告。
- 最新库存、采购和广告状态作为最新快照独立标注；不得改写成历史日期库存。
- 重新向DeepSeek传入新区间数据包，不只替换标题和时间文字。
- 保留范围权限；不能因改日期扩店铺或PID。若历史映射生效期变化，应由后台明确同一分析对象在新窗口的有效关联，异常列待核。
- 每次请求绑定对象和日期；旧请求晚返回不能覆盖新请求。避免连续点击重复提交；缓存必须包含授权范围、对象、日期、时区、快照及提示词版本。
- 生成失败保留用户修改后的日期以便重试；如继续展示旧报告，必须明确旧报告日期且不宣称已更新。不能拿旧数字充当新结果。

### 下载与验收
