## 3. 每种关键结论对应哪个来源
- “销量涨跌”：S01。S02用于定位板块、PID贡献；口径冲突须并列解释，不静默替代S01。
- “哪个渠道导致变化”：S02 + S01对账。渠道无件数时仅说明金额/订单变化。
- “历史第一个素材开单日”：S04线索 + S05经营开单历史核验；该店铺/PID历史范围清楚，不能以S03广告归因首单替代。
- “累计发布/本期发布”：S04，不能拿S02挂车累计或S03报表行数代替。
- “本期发布且本期有单”：S04发布队列与S05同窗口经营业绩交集；S03广告效果另列。
- “素材投广占比”：S04发布集合与S03同PID有消耗集合对齐去重；数据完整后算交集/分母。
- “当前投放状态占比”：S03最新状态 + 已核完整候选集合，状态时点明确；不是S04 adVideo布尔标签。
- “商务/剪辑表现”：S04/S05/S03视频集合 + S06发生日有效归属。S07补寄样履约，不能拿寄样量当视频发布量。
- “热卖码断码”：S08 + S01 SKU销量 + S11映射；必要时S12回看断货前正常需求。
- “SKU何时接上货”：S08现存 + S09采购交货 + S10实际物流/入库/可售 + S11映射，IT计算时间线。
- “补货后旧素材是否恢复”：S12实际可售恢复证据 + S05/S03固定同一视频队列。
- “广告放缩/加热”：S01/S02/S03 + S08/S09/S10；成本门槛有S13证据才可使用，缺失不假定盈利。

## 4. 采购与SKU接货：交给IT的明确要求
### 4.1 关联粒度
按“当前店铺+SPU→实际TK SKU（颜色尺码）→ERP库存SKU→采购订单行→交货/发货批次→目标仓/店铺可售”关联。
仅凭SPU名称相同不够：需核商品映射、订单用途/分配数量、目标仓与平台归属，防止把其他平台/店铺预留货当作本店可接续库存。

### 4.2 字段清单
采购：采购单号、明细ID、SKU、颜色尺码、供应商、目标仓/业务、状态、下单量、取消量、已交量、未交量、原定预计交货日、最新确认/修订交货日、实际交货日、更新人/时间。
物流与仓储：关联采购/交货单号、批次ID、SKU、运输方式、发出量/未收量、发出日、预计/实际国内到仓、预计/实际目标仓到仓、预计/实际可售、上架/同步状态及时间。
分清未知与零；按单据状态互斥归类，禁止采购在途与同批物流在途重复加总。

### 4.3 日期链
供应商预计交货 → 国内入库/质检 → 国际运输/清关 → 目标仓入库/上架 → 店铺同步可售。
只取到前一步时，后续标未知；有物流与上架时效模型才可计算“估算可售区间”，标参数、来源、可信度，不把估计当确认交期。
预计交货延迟不自动等于销量损失；只有库存/需求/可售时间线结合后才能判断是否断档。

### 4.4 报告表头
重点跟进标签｜SKU/颜色尺码｜是否热卖及依据｜风险状态｜当前可售｜基线日销与窗口｜预计耗尽日｜采购/批次｜未完成/可分配量｜最新预计交货日｜预计目标仓可售日或区间｜断档天数/区间｜到货后覆盖｜来源/可信度。
按批次逐日加入可售量，扣除到货前需求；主销码分开，不能只给SPU平均到货日。
缺失预计可售日时显示“已有预计交货，接货日期仍待核实”，不输出肯定可放量。

### 4.5 热卖色码重点跟进
用户已明确：SKU需要打标，热卖色码作为重点跟进对象。
- 标签名称：重点跟进·热卖色码。标签绑定具体SKU/颜色尺码，不能仅标SPU或颜色后将全部尺码一起视为热卖。
- 报告重点清单默认展示热卖色码，其余SKU保留汇总和展开明细；仅收敛展示，不删除底层明细或从库存计算中排除。
- 热卖标签与风险状态分开：是否热卖回答是否重点跟，缺货/预计断档/交期未知/同步异常回答当前为什么要跟。
- 建议排序：已断码 → 已有证据预计接不上 → 交期或可售日期未知 → 其他临近风险 → 正常热卖码；同类参考销量贡献和断档程度，不硬编码固定数量上限。
- 每行展示积加采购单/批次、未交数量、最新预计交货、预计可售、耗尽与断档；支持追溯该SKU来源和日期更新。
- 热卖来源已定位：TK Center商品统计SKU看板tk_product_sku_stats_query返回isHotColorSize（是/否），直接沿用。保留店铺/PID/SKU与标签所属日期/窗口；跨期多值由IT核源分组与时点后处理。撤回重建热卖算法和人工打标流程建议，DeepSeek不改写源标签。
- 不因断货后销量下降就自动移除热卖标签；标签依据和观察窗口要可追溯，恢复后按明确规则复核。
- IT建议输入字段（非已验证源字段）：is_hot_sku、focus_followup、hot_basis/source/window、risk_status、procurement_batches。未知标签为null，不能默认为false。
### 4.6 积加MCP真实字段定位（2026-09-23补充）
证据见[采购字段定位](积加采购字段核查_1412/采购交期未交量字段定位.md)。采购列表取单号，采购详情使用 `data.warehouseProcureItemVos[].procureItemVos[]` 的分仓SKU行：`delayExpectDeliveryDate`预计交期、`balanceQuantity`未交量；另保留`expectDeliveryDate`合同交期、`planExpectDeliveryDate`计划交期、`actualDeliveryDate`实际交期及`lotNoCode`交货单号。
真实PO2602064883中的AL-W0199-LL-L汇总23件，Amazon仓14件、TK厦门直邮仓9件。只按SPU/SKU而不分业务仓会误计TK数量。
履约路线必须分支：国内直邮在实际国内履约仓入库/上架同步后核可售；海外/FBT路线才需要继续核国际运输、目标仓上架。不得把所有TK货统一视为必须到美国仓。
当前库存页未发货汇总与两SKU积加采购查询未对齐；该样例为已完成历史单，不代表现有在途交期。热卖标签在后续商品统计SKU接口核查中已找到，详见TK热卖字段核查_1443/热卖字段纠正与接入说明.md。

## 6. 所有数据源统一登记
