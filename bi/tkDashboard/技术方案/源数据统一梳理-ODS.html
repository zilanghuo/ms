tkDashboard 源数据统一梳理（ODS）

本文只保留 已集成的 ODS 列表明细，用于后续业务排查时快速确认：当前有哪些贴源表已经接入、每张表对应什么源数据、来源系统是什么、当前被哪些页面或场景使用。不展开 DWD / DWS / ADS。

使用方式
  • 优先按 ODS 表名查，再看它对应的源数据、使用页面和排查重点。
  • 若页面数据异常，优先核对该 ODS 表当天是否有数、店铺名是否正常、业务日期是否落对。
  • 本文基于现有需求文档、接口设计文档、技术方案与表结构设计整理，口径以当前已集成表为准。

ods_sales_api_jijia_omnichannel_order_item_di 全渠道销售订单明细表 积加 API / Shopify 侧订单明细 提供商品粒度订单明细，支撑商品销量和订单主子表核对 店铺统计 / 商品统计 重点核对订单主子表是否能按订单号关联上，商品件数是否完整

三、排查建议

  • PID 数据看板异常时，先查 ods_traffic_file_tiktok_product_list_di，因为它是主底表，缺它通常整行指标都出不来。
  • 广告数据异常时，优先查 ods_marketing_file_tiktok_campaign_di 的 campaign_name 是否还能正确解析 PID。
  • 视频 / 挂车数据异常时，联查 ods_traffic_file_tiktok_video_performance_di 和 ods_platform_file_tiktok_account_df，先确认达人 ID 是否可匹配。
  • 商品维度补不出来时，优先查 ods_product_api_jijia_omnichannel_product_df 中商品标题、父 ASIN、Seller SKU 等关键字段。
  • GMV 计算异常时，先看 ods_trade_api_tiktok_order_di 和 ods_trade_api_tiktok_order_item_di 是否同批次、同日期完整入仓。
  • 店铺统计 / 商品统计异常时，先查 ods_sales_api_jijia_omnichannel_order_di 与 ods_sales_api_jijia_omnichannel_order_item_di 的订单主子表是否一致。
