三、当前表结构统一规范建议

说明

以下建议基于当前 DDL 目录已有表结构归纳，目的是让后续新增表、补字段、跨模块关联时，字段命名和口径更统一。该部分适合作为库存模块、后续新增业务模块的字段设计参考。

规范类别建议统一方式当前观察到的问题
业务日期字段统一保留 smt 作为月分区字段，格式 YYYYMM；统一保留 sdt 作为业务日期字段，格式 YYYYMMDD；小时分区统一 sht 或 hour。现有表大多有 sdt，但部分表缺少 smt，部分表又同时存在 order_date / payment_date / *_market，语义容易混淆。后续新表建议默认同时保留 smt 和 sdt。
店铺字段统一优先使用 store_id、store_code、store_name；若是业务前端口径为“店铺”，不要混用 shop_id / shop_name。platform / sales / inventory 场景里有 store_* 和 shop_* 两套叫法，后续跨模块会增加映射成本。
站点字段统一使用 site_id、site_code、site_name；若是店铺站点维度，用 store_site_id、store_site_code、store_site_name。现有部分表只保留 store_site_*，部分业务文档直接写“站点”，需要明确是“站点”还是“店铺站点”。
平台字段统一使用 platform_id、platform_code、platform_name。整体较统一，但个别文件说明未明确平台字段是否为主数据口径。
商品标识字段统一按层次保留 spu、sku、msku、pid，必要时增加 product_id、item_id；字段名不要简写成业务内隐式缩写。不同模块对 PID、ASIN、父 ASIN、product_id 的叫法不同，建议后续在字段注释中明确“一对一对应关系”。
状态字段状态类字段统一成“编码 + 名称”双字段，例如 order_status + order_status_name，或 product_status_code + product_status_name。当前有的用 status，有的用 status_name，有的又带 desc 后缀，不够统一。
金额字段金额统一 DECIMAL(20,4) 为主；若为费率、比例，统一明确百分比还是小数值。当前部分点击率/转化率字段使用 VARCHAR，部分用 DECIMAL，后续统计易出问题。
汇率与币种统一使用 currency_code、exchange_rate、amount_rmb 等规范命名。个别表使用 currency，个别表使用 currency_code，建议新表统一到后者。
时间字段业务时间统一明确北京时区和市场时区，建议配对使用 xxx_time 与 xxx_time_market，日期配对使用 xxx_date 与 xxx_date_market。销售域已基本形成规范，其他模块后续新增表应直接复用，避免只有一个时间字段但语义不明确。
插入时间统一使用 insert_time，表示系统入仓或产出时间。现有部分表仍在使用 etl_time，但后续新表不再新增该写法，统一收敛到 insert_time。
主键与唯一键前缀在 Doris UNIQUE KEY / 明细表设计中，唯一键字段应尽量放在 DDL 前部，并与分区字段形成稳定前缀。销售域 DWD 已有较明确规范，后续新模块可以直接沿用这一写法。

四、建议优先统一的字段口径

  • “店铺”统一为 store_*，“店铺站点”统一为 store_site_*，“站点”统一为 site_*，避免 shop_* 与 store_* 并存。
  • 比例类字段不建议再落 VARCHAR，应统一成 DECIMAL；页面展示百分号在应用层处理。
  • 凡是状态字段，建议统一补齐编码字段和名称字段，避免只保留一个中文描述列。
  • 凡是金额字段，建议明确“原币”还是“人民币”，并通过字段名体现，不要只靠注释区分。
  • 新增库存模块相关表时，建议直接复用销售域已经形成的时间、店铺、站点、币种命名体系，减少后续跨模块联表转换。
  • 历史表不做统一改名；从当前开始，新建表和新增字段统一按“不规范字段对照表”的推荐字段名执行。
  • 新表默认同时保留 smt 和 sdt，其中 smt 为分区字段，sdt 为业务日期；插入时间统一使用 insert_time。

六、使用建议

  • 如果是做新需求落表，优先参考现有模块与分层归属，避免同类数据分散到多个模块。
  • 如果是做库存模块表设计，可把本页作为“现有表参考清单”，再结合 Doris 规范独立设计新表。
  • 若后续继续细化，可新增“字段级明细”子页，按模块分别维护，不建议把所有字段直接堆在同一页。
