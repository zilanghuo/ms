管理模块 表结构设计

本文档为 bi/tkDashboard/管理模块 的统一表结构设计，当前覆盖 商品模块/商品档案.html、账号模块/账号维护.html、视频数据/视频数据.html 与内部运营人员配置。表结构按 Doris 兼容语法与 ms-warehouse-batch-data/AGENTS.md 命名规范设计。

命名依据：管理模块只是页面归属，不作为数仓业务域入表名；商品档案、账号维护与视频数据均归入商品域，优先使用 dim_product_xxx_config 配置维表命名；公司内部人员配置归入组织域，使用 dim_organization_xxx_config 当前生效配置维表命名；如后续需要保留每日快照或历史版本，再新增 _df 快照表或历史流水表。

一、表清单

层级表名服务页面粒度 / 主键说明
DIMdim_product_archive_config商品档案平台 + 店铺 + PID + SKU商品档案当前生效配置，承接 TK API、积加商品主数据与人工维护字段。
DIMdim_organization_internal_staff_config商品档案；后续可复用到账号维护 / 视频数据 / 寄样管理内部人员 ID公司内部运营、商务、编导、剪辑、直播、投放等人员配置。
DIMdim_platform_tiktok_account_config账号维护TikTok UIDTikTok 账号当前生效档案，手动维护渠道号、达人号、TAP 机构号及运营归属。
DIMdim_product_tiktok_video_config视频数据视频 IDTikTok 视频当前生效配置，承接已绑定账号 / 联盟账号源数据与人工维护字段。

二、设计原则

  • 商品档案：基础数据来源于 TK API 与积加商品主数据；主图取 SKU 主属性图第一张；产品主 SKU 决定价格归属；其他运营字段支持人工维护。
  • 内部人员：商品档案中的 operator_owner、business_owner、guidance_owner、editor_owner、live_owner、ad_owner 当前仍保存展示姓名；后续页面可从内部人员 DIM 表加载下拉选项，避免手输姓名不统一。
  • 账号维护：页面说明为手动维护，无第三方 API 数据源；登录凭证类内容正式落库时必须加密或脱敏存储。
  • 视频数据：视频基础信息与源数据来源于已绑定账号和联盟账号；列表、编辑抽屉与视频源数据维护中的可保存字段统一沉淀到商品域 DIM 层。
  • 字段命名：底表字段使用小写下划线；页面接口字段如后续实现，仍使用 Java DTO / VO 驼峰命名。
  • 状态字段：当前页面以中文枚举展示，底表保留 status_name 等展示字段；如后续需要统一枚举，可补充 status_code。

    daily_sale_price              DECIMAL(18,4)  COMMENT '日常折线价',

四、dim_organization_internal_staff_config

公司内部人员当前生效配置表，支撑商品档案运营人员相关字段下拉选择；后续也可复用到账号维护、视频数据、寄样管理等页面的人员归属字段。

字段名类型来源 / 维护方式说明
staff_idVARCHAR(100)人工维护 / 企业微信内部人员 ID；暂无企业微信 ID 时先用人工维护编码，后续可映射企业微信 user_id。
staff_nameVARCHAR(100)组织架构 / 人工维护中文姓名。
english_nameVARCHAR(100)组织架构 / 人工维护英文名或常用英文称呼；按截图原文保留大小写。
display_nameVARCHAR(200)系统拼接 / 人工维护页面展示名，如“杨滨羽 Ava”；无英文名时仅展示中文姓名。
root_department_nameVARCHAR(200)组织架构 / 人工维护根部门，如美国 TikTok 运营部。
department_nameVARCHAR(200)组织架构 / 人工维护一级业务组，如海外商务组、运营支持组、短视频剪辑组。
team_nameVARCHAR(100)组织架构 / 人工维护小组名称，如一组、二组；无小组时可为空。
staff_role_nameVARCHAR(200)人工维护可用人员角色，如运营、商务、编导、剪辑、直播、投放；多个角色用逗号分隔。

CREATE TABLE IF NOT EXISTS dim.dim_organization_internal_staff_config (

    team_name                    VARCHAR(100)   COMMENT '小组名称',
    staff_role_name              VARCHAR(200)   COMMENT '人员角色，逗号分隔',
    is_enabled                   TINYINT        DEFAULT '1' COMMENT '是否启用',
    sort_no                      INT            DEFAULT '0' COMMENT '展示排序',
    remark                       STRING         COMMENT '备注',
    created_time                 DATETIME       COMMENT '创建时间',
    updated_time                 DATETIME       COMMENT '更新时间',
    insert_time                  DATETIME       DEFAULT CURRENT_TIMESTAMP COMMENT '入仓时间'
) ENGINE=OLAP
UNIQUE KEY(staff_id)
COMMENT '组织域内部人员当前生效配置表'
DISTRIBUTED BY HASH(staff_id) BUCKETS 4
PROPERTIES (
    "replication_num" = "1"
);
