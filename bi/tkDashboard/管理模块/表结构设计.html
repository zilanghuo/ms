管理模块 表结构设计

本文档为 bi/tkDashboard/管理模块 的统一表结构设计，当前覆盖 商品模块/商品档案.html、账号模块/账号维护.html 与 视频数据/视频数据.html 页面。表结构按 Doris 兼容语法与 ms-warehouse-batch-data/AGENTS.md 命名规范设计。

命名依据：管理模块只是页面归属，不作为数仓业务域入表名；商品档案、账号维护与视频数据均归入商品域，优先使用 dim_product_xxx_config 配置维表命名；如后续需要保留每日快照或历史版本，再新增 _df 快照表或历史流水表。

一、表清单

层级表名服务页面粒度 / 主键说明
DIMdim_product_archive_config商品档案平台 + 店铺 + PID + SKU商品档案当前生效配置，承接 TK API、积加商品主数据与人工维护字段。
DIMdim_product_tiktok_account_config账号维护TikTok UIDTikTok 账号当前生效档案，手动维护渠道号、达人号、TAP 机构号及运营归属。
DIMdim_product_tiktok_video_config视频数据视频 IDTikTok 视频当前生效配置，承接已绑定账号 / 联盟账号源数据与人工维护字段。

二、设计原则

  • 商品档案：基础数据来源于 TK API 与积加商品主数据；主图取 SKU 主属性图第一张；产品主 SKU 决定价格归属；其他运营字段支持人工维护。
  • 账号维护：页面说明为手动维护，无第三方 API 数据源；登录凭证类内容正式落库时必须加密或脱敏存储。
  • 视频数据：视频基础信息与源数据来源于已绑定账号和联盟账号；列表、编辑抽屉与视频源数据维护中的可保存字段统一沉淀到商品域 DIM 层。
  • 字段命名：底表字段使用小写下划线；页面接口字段如后续实现，仍使用 Java DTO / VO 驼峰命名。
  • 状态字段：当前页面以中文枚举展示，底表保留 status_name 等展示字段；如后续需要统一枚举，可补充 status_code。

    ad_owner                      VARCHAR(100)   COMMENT '投放负责人',
    tag_price                     DECIMAL(18,4)  COMMENT '吊牌价',
    daily_sale_price              DECIMAL(18,4)  COMMENT '日常折线价',
    live_flash_price              DECIMAL(18,4)  COMMENT '直播间秒杀价',
    campaign_price                DECIMAL(18,4)  COMMENT '活动报名价',
    amazon_price                  DECIMAL(18,4)  COMMENT '亚马逊定价',
    site_price                    DECIMAL(18,4)  COMMENT '独立站价格',
    public_commission_rate        DECIMAL(18,4)  COMMENT '公开佣金比例',
    target_commission_rate        DECIMAL(18,4)  COMMENT '定向佣金比例',
    ad_commission_rate            DECIMAL(18,4)  COMMENT '广告佣金比例',
    ippc_register_status          VARCHAR(50)    COMMENT 'IPPC 注册情况',
    ippc_remark                   STRING         COMMENT 'IPPC 情况说明',
    product_selling_points        STRING         COMMENT '产品卖点',
    source_update_date            DATE           COMMENT '源数据更新日期',
    is_deleted                    TINYINT        DEFAULT '0' COMMENT '逻辑删除标记',

COMMENT '商品域商品档案当前生效配置表'
DISTRIBUTED BY HASH(pid) BUCKETS 16
PROPERTIES (
    "replication_num" = "1"
);

四、dim_product_tiktok_account_config

字段名类型来源 / 维护方式说明
tiktok_uidVARCHAR(100)人工维护TikTok UID，账号唯一主键。
handle_nameVARCHAR(200)人工维护Handle Name，如 @faiable_official。
handle_urlSTRING人工维护账号主页 URL；页面支持编辑 URL。
account_type_nameVARCHAR(50)人工维护账号类型：渠道号、达人号、TAP 机构号。
site_codeVARCHAR(30)人工维护国家 / 站点，如 US、UK、AU。
cart_store_nameVARCHAR(200)人工维护内容挂车店铺。
operator_ownerVARCHAR(100)人工维护运营人员。
account_status_nameVARCHAR(50)人工维护账号状态：活跃、暂停、停用。
position_gender_nameVARCHAR(20)人工维护账号定位性别：未知、女、男。
credential_cipher_textSTRING人工维护 / 加密存储登录凭证密文；正式系统不得明文保存。
credential_remarkSTRING人工维护登录凭证备注 / 授权说明。
is_deletedTINYINT系统字段逻辑删除标记；回收站使用。
created_timeDATETIME系统字段创建时间。
updated_timeDATETIME系统字段更新时间。

字段名类型来源 / 维护方式说明
video_idVARCHAR(100)已绑定账号 / 联盟账号TikTok 视频 ID，视频记录唯一主键。
tiktok_uidVARCHAR(100)已绑定账号 / 联盟账号达人 UID；用于关联账号维护与寄样记录。
creator_idVARCHAR(100)已绑定账号 / 联盟账号达人 ID，视频源数据维护弹框展示与查询使用。
creator_account_nameVARCHAR(200)已绑定账号 / 联盟账号达人账号 / Handle Name，列表“达人账号”。
store_nameVARCHAR(200)已绑定账号 / 联盟账号店铺名，视频源数据维护列表展示。
video_nameSTRING已绑定账号 / 联盟账号视频名称，视频源数据维护列表展示。
video_urlSTRING已绑定账号 / 联盟账号视频链接，列表与抽屉跳转 TikTok 使用。
publish_timeDATETIME已绑定账号 / 联盟账号发布时间，支持日期筛选。
video_type_nameVARCHAR(50)系统识别 / 人工维护视频类型：联盟、自制、图文、AI。
content_type_nameVARCHAR(50)系统识别 / 人工维护内容类型：混剪、实拍、达人原生、达人AI、图文、达人图文、AI。

product_nameVARCHAR(500)人工维护商品名称，视频源数据编辑弹窗唯一可调整字段。
data_source_nameVARCHAR(50)已绑定账号 / 联盟账号数据来源：已绑定账号、联盟账号。
owner_businessVARCHAR(100)人工维护归属商务，视频记录编辑抽屉维护。
auth_codeVARCHAR(100)人工维护授权码，视频记录编辑抽屉维护。
video_color_nameVARCHAR(100)人工维护视频颜色，视频记录编辑抽屉维护。
sample_businessVARCHAR(100)人工维护 / 寄样记录匹配寄样商务，可基于匹配到的寄样记录带出或人工维护。

5.2 视频源数据维护弹框字段覆盖

“视频源数据维护”列表与“编辑视频源数据”弹框字段同样落入 dim_product_tiktok_video_config。其中仅 product_name 当前支持人工编辑，其余字段来自已绑定账号或联盟账号并只读保存。

弹框字段对应表字段读写方式说明
店铺名store_name只读保存来源于已绑定账号 / 联盟账号源数据。
视频IDvideo_id只读保存视频记录唯一键。
视频名称video_name只读保存源数据维护列表与编辑弹框展示。
达人IDcreator_id只读保存源数据维护查询条件与弹框字段；如能映射 TikTok UID，可同步写入 tiktok_uid。
商品名称product_name人工编辑当前原型唯一允许调整的源数据字段。
发布时间publish_time只读保存源数据维护日期筛选与列表展示字段。
数据来源data_source_name只读保存枚举值：已绑定账号、联盟账号。
