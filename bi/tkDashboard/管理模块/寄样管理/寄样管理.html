内容说明

一、页面说明

  1. 看板字段以 TikTok_IT映射表_寄样管理.xlsx 的 映射表 sheet 为准，一级模块为寄样管理，二级模块对应表单分区。
  2. 寄样订单指样品订单，可通过 TK 订单详情中的样品订单标识 is_sample_order 识别。
  3. 列表字段按 站点 / 店铺 - 运营信息 - 达人信息 - 产品信息 - 订单物流补充 的顺序展示，便于先确认业务归属，再查看达人、SKU、PID 和履约状态。

二、重新梳理后的准确逻辑

  1. 订单数据来源：订单数据来源于 TikTok API 的订单明细，仅取订单类型为 is_sample_order 的样品订单。
  2. 列表数据粒度：本页面按 SKU 维度 拆分展示。若一个订单包含 3 个不同 SKU，则拆成 3 行记录；每行可分别对应不同 PID / Product ID。
  3. 达人信息维护：达人 ID、达人名字、达人等级、达人性别、是否开单达人、合作阶段、达人佣金、备注等达人相关信息通过手动编辑维护。
  4. 寄样状态关联逻辑：寄样状态需要与视频数据关联判断，寄样订单与视频数据通过 PID + 达人信息 进行匹配。
  5. 履约逾期判断：以订单签收日期为起点，签收后 0-6 天内若未关联到对应视频，不算逾期，订单仍处于正常待履约状态；签收后达到或超过 7 天（>= 7 天）仍未关联到视频时，判定为逾期。
  6. 编辑补充达人：编辑寄样记录时，如果达人列表中未出现对应达人，支持手动填入达人相关信息；保存后默认同步写入账户维护（达人）列表，后续可在账户维护中继续维护。
  7. 签收时间来源：物流签收时间优先取订单 API 的 delivery_time 字段；若接口暂未返回 delivery_time，则通过跟踪号码接物流查询获取签收日期。

三、逾期提醒 Demo

  1. 物流签收示例：订单 order01，寄样商务 X，达人 A，产品 B，2026-07-10 寄样。系统通过订单 API 的 delivery_time 获取签收时间；若 delivery_time 为空，则通过跟踪号码查询物流签收结果。本例 2026-07-17 签收，未超过 7 个自然日，物流侧不算逾期。
  2. 视频履约示例：订单 order01 对应达人 A、PID 为产品 B；达人在 2026-07-24 发布并关联到对应视频 VID，则计入履约。如果 2026-07-24 仍未通过 PID + 达人信息关联到视频，则签收后已达到 7 天，标记为“履约逾期”，进入逾期提醒筛选。
