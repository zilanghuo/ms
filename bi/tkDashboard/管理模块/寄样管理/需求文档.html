寄样管理需求文档

本文档对应 bi/tkDashboard/管理模块/寄样管理/寄样管理.html，依据最新 TikTok_IT映射表_寄样管理.xlsx 的 映射表 sheet 更新，用于明确寄样管理页面的列表展示、筛选、编辑、导出、数据来源与字段口径。

核心口径：一级模块为「寄样管理」；二级模块对应页面表单分区，包括达人信息、商品信息、订单信息、业务信息。字段名称、字段解释、数据来源、计算逻辑、使用功能均以最新 Excel 映射表为准。

一、需求概述

需求名称寄样管理
所属模块tkDashboard / 管理模块
原型页面管理模块/寄样管理/寄样管理.html
需求来源管理模块/寄样管理/TikTok_IT映射表_寄样管理.xlsx / 映射表
优先级高
目标用户商务、运营、寄样跟进人员、管理人员。
核心价值统一管理达人寄样过程，将达人账号档案、商品档案、寄样订单与业务维护信息沉淀为可查询、可编辑、可导出的寄样台账。

1.1 建设目标

  1. 支持按达人信息、商品信息、订单信息、业务信息管理寄样记录。
  2. 支持列表查看、组合筛选、关键字模糊 / 精确搜索、逾期提醒、导出、新增、编辑、删除。
  3. 支持达人 ID 与账号维护模块联动，自动带出达人名字、达人等级、达人性别、是否开单达人。
  4. 支持寄样主SKU与商品档案联动，自动带出商品名称，并可关联查看商品详情。
  5. 以「达人ID（TIKTOK ID）+ 寄样SKU」作为查重主键，第二条相同组合自动标注补寄。
  6. 寄样时间按 UTC 存储，前端支持 PT / CST 双时区展示；寄样月份由寄样时间自动计算。

三、编辑弹窗

编辑弹窗按 Excel 的二级模块分组，覆盖全部 25 个目标字段。保存后，人工维护字段以寄样管理保存结果为准。

分区字段来源 / 规则要求
达人信息达人ID（TIKTOK ID）、达人名字、达人等级、达人性别、是否开单达人达人ID可手工录入；其余字段输入达人ID后从账号维护匹配带出。达人ID必填；达人ID + 寄样SKU 作为查重主键。

订单信息积加订单编号、合作店铺、合作站点、寄样渠道、物流状态、补寄情况订单字段手工维护；补寄情况可系统自动标注或手工录入。合作店铺、合作站点、寄样渠道使用枚举；物流状态为自由文本。

3.1 保存规则

  1. 保存时校验必填项：达人ID（TIKTOK ID）、寄样SKU、寄样主SKU、寄样数量、寄样时间、寄样商务、寄样状态、达人佣金。
  2. 输入达人ID后，系统从账号维护匹配并带出达人名字、达人等级、达人性别、是否开单达人。
  3. 输入寄样主SKU后，系统从商品档案匹配并带出商品名称，可用于关联查看商品详情。
  4. 同一达人ID + 同一寄样SKU第二次出现时，系统自动在补寄情况中填入「补寄」。
  5. 寄样时间统一存储为 UTC ISO 字符串；寄样月份根据寄样时间自动生成。
  6. 删除操作按逻辑删除处理，不直接物理删除原始订单或维护数据。

五、数据来源与处理流程

5.1 数据来源

来源用途关键字段说明
手工录入 / 寄样维护数据维护寄样业务字段和人工补充字段。达人ID、寄样SKU、寄样主SKU、定向Product ID、积加订单编号、合作店铺、合作站点、寄样渠道、物流状态、寄样时间、寄样商务、寄样状态、合作阶段、达人佣金、备注。页面编辑保存后的人工维护值优先展示。
账号维护根据达人ID自动带出达人信息。tiktokId、nickname、influencerLevel、influencerGender、isOrderInfluencer。用于减少重复录入，并支持达人维度筛选。
商品档案根据寄样主SKU自动带出商品信息。mainSku、productName。用于将寄样SKU与商品主数据打通，可关联查看商品详情。
系统计算生成计算字段和辅助标记。sampleMonth、reshipNote。寄样月份由寄样时间计算；补寄情况由查重规则自动标注。

5.2 处理流程

  1. 业务人员新增或编辑寄样记录，录入达人ID、寄样SKU、寄样主SKU、寄样时间、寄样商务、寄样状态等必填字段。
  2. 系统根据达人ID关联账号维护，带出达人名字、达人等级、达人性别、是否开单达人。
  3. 系统根据寄样主SKU关联商品档案，带出商品名称，并保留定向Product ID、颜色、尺码、数量等寄样明细。
  4. 保存时按达人ID + 寄样SKU查重；同一组合第二条及之后记录，补寄情况自动标注「补寄」。
  5. 系统根据寄样时间生成寄样月份，并支持按时间范围、月份、状态、阶段、等级、性别、商务、店铺、站点等条件查询。
  6. 导出时包含列表字段和默认隐藏字段，保证映射表 25 个目标字段完整输出。

5.3 数据覆盖优先级

  1. 人工维护字段以寄样管理页面保存结果为准。
  2. 达人名字、达人等级、达人性别、是否开单达人默认以账号维护关联带出值为准。
  3. 商品名称默认以商品档案关联带出值为准。
  4. 寄样月份、补寄情况等计算字段由系统计算生成；如支持人工修正，应保留修正记录和操作人。

六、导出与异常提醒

  • 导出：默认导出当前筛选条件下的寄样记录；字段应覆盖 Excel 映射表中的 25 个目标字段。
  • 默认隐藏字段：寄样颜色、寄样尺码、寄样数量、合作店铺、合作站点、寄样渠道、物流状态、补寄情况、达人佣金、备注不在列表默认展示，但需要在编辑弹窗维护并在导出中输出。
  • 逾期提醒：用于快速筛选运输中、签收待履约或超过配置时限仍未履约的记录。
  • 异常标记：签收异常、物流超时、补寄记录等需要在列表中高亮，并进入异常统计。
  • 数据更新时间：正式页面应展示寄样台账更新时间，便于判断数据新鲜度。

七、验收标准

  1. 页面可从首页「管理模块 / 寄样管理」进入，并可跳转到寄样管理原型。
  2. 需求文档、原型页面与 TikTok_IT映射表_寄样管理.xlsx 字段一致，覆盖 25 个目标字段。
  3. 筛选区支持寄样状态、合作阶段、达人等级、达人性别、是否开单达人、寄样商务、寄样主SKU、合作店铺、合作站点、寄样月份、寄样时间范围和关键字搜索。
  4. 列表默认展示核心字段：寄样时间、寄样月份、达人ID、达人名字、达人等级、达人性别、是否开单达人、寄样SKU、寄样主SKU、商品名称、定向Product ID、积加订单编号、寄样商务、寄样状态、合作阶段。
  5. 编辑弹窗按达人信息、商品信息、订单信息、业务信息分区，并能维护所有非纯展示字段。
  6. 达人ID能联动账号维护带出达人信息；寄样主SKU能联动商品档案带出商品名称。
  7. 同一达人ID + 寄样SKU再次出现时，系统能自动标注补寄。
  8. 寄样时间按 UTC 存储，寄样月份自动计算，前端支持 PT / CST 展示口径。
  9. 导出字段覆盖完整映射表字段，逾期提醒和异常高亮符合原型展示口径。
