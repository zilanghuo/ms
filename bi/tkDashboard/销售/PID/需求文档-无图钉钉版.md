## 一、需求一：PID 维度 GMV 计算表

| 项目 | 内容 |
| --- | --- |
| 优先级 | — |
| 影响面 | — |
| 价值 | 1、原先每天0.5小时人工处理，频次一个月30天，每个月可节省 15小时；2、系统化，可介入AI进行数据分析；3、支持更复杂的页面展示，内容明细及跳转 |

### 1.1 需求描述

- **输入**：源数据统一梳理中的 5 张表，尤其是全部笔订单、全渠道商品表，加上映射表规则。
- **参照**：`1店PID维度的数据监测工具表-7天数据` 中的 **GMV计算** 结构与字段。
- **目标**：按店铺、按 PID 产出“GMV 计算”数据表，为数据看板提供客单价、补贴、总 GMV 等。
- **店铺**：同上。

### 1.2 流程

1. 从“全部笔订单”提取 Paid Time 日期；通过 全部笔订单.Seller SKU 关联 全渠道商品表.父ASIN 得到 PID。
2. 按映射表规则筛选，如 Cancelation/Return Type 不等于 Cancel，按 PID 汇总营业总额、商家折扣、补贴、运费、单量、实付总价等。
3. 计算：
   - 总GMV = 营业总额 - 商家折扣 + 运费
   - 每单补贴 = 补贴 / 单量
   - 客单价 = 实付总价 / 单量，保留两位小数
4. 店铺字段由导出店铺或人工设置。
5. 产出：`1店PID维度的数据监测工具表-7天数据-》GMV计算`，或等价多店表，供数据看板使用。

### 2.4 实现逻辑梳理（落库与计算）

1. **ODS 入仓**：按店铺 + 日期导出并入仓 4 张 ODS 表：
   - `ods_traffic_file_tiktok_product_list_di`
   - `ods_marketing_file_tiktok_campaign_di`
   - `ods_traffic_file_tiktok_video_performance_di`
   - `ods_platform_file_tiktok_account_df`
   - 全渠道商品表为 `ods_product_api_jijia_omnichannel_product_df`
2. **确定主键**：数据看板主键建议为 `(sdt, store_name, pid)`，其中 `pid = product_list.product_id`
3. **维度补全**：通过全渠道商品表补全 `spu` 等商品维度
4. **GMV 计算来源**：客单价、补贴等可直接取 `dws_sales_pid_gmv_calc_realtime_detail`
5. **广告指标**：从 `ods_marketing_file_tiktok_campaign_di` 按 `sdt + store_name` 聚合，并从 `campaign_name` 解析 pid
6. **挂车 / 视频指标**：从 `ods_traffic_file_tiktok_video_performance_di` 按 `sdt + store_name` 聚合；剪辑挂车用 `creator_id` 命中 `ods_platform_file_tiktok_account_df.tiktok_uid`
7. **产出 ADS**：最终日表输出到 `ads_sales_pid_dashboard_1d`

### 2.5 最终目标结果

需求二达成的目标：**PID 维度数据看板**，支持按日期、店铺、PID 筛选，展示 GMV、渠道占比、商品卡/直播/短视频指标及广告挂车、ACOAS、广告ROI（测算）、广告AcoAs 等。
