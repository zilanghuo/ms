标准化字段		identity/video/info → data.video_detail.auth_info.auth_start_time，已真实验证。记录授权生效时间，用于审计与异常排查。仅做追溯，不单独决定有效/过期。
identity_type=AUTH_CODEgmv_max/video/get → identity_info.identity_type 已有真实样例。辅助识别素材关联授权码身份。不是生命周期字段；没有截止时间、状态枚举或撤销原因，不能用来计算过期。

兜底规则：如果步骤②在首次联调中未返回“授权状态 + 可换算的截止时间”两个信息，素材生命周期只能显示 PENDING；页面不得出现“过期素材数”或“当前可用素材数”的经营结论。此时需继续向 TikTok 确认可用字段或改由授权主数据提供到期时间。

五、VSA 专项链路

不能用 GMV Max 识别 VSA。gmv_max/campaign/get 与 Campaign 详情中的 shopping_ads_type=PRODUCT 仅描述 GMV Max 商品投放类型，不是 VSA 标记。VSA 必须在普通 Ad Group 层识别，再回连 Ad Group 日报汇总。
普通 Campaign（归属） → 普通 Ad Group（判定 adFormat=VSA） → Ad Group 日报（按日消耗） → 过滤 VSA → Campaign / 项目汇总
真实链路验证（2026-10-16）：使用授权账户以只读方式依次请求 Campaign、指定 Ad Group 与指定 Ad Group 分日报，三次均返回 code=0。日报在补齐必填 report_type=BASIC 后成功返回 5 个日粒度记录；该广告组在测试期间已停用，因此三项效果指标均为 0。这证明 API 链路可用，不是接口卡点；仍需补内部代理、ODS 和调度。

六、卡点与优先级

优先级卡点事实依据影响范围建议动作 / 验收
P0VSA API ODS 与调度链未落地普通 Campaign、Ad Group、集成报表接口及内部只读代理均已可用，并已有联调记录；但 ddl/marketing/ods 尚无对应 API ODS，当前只有文件导入表。VSA 消耗、格式区分、与 GMV Max 汇总、按广告对象追溯。新增 3 张 API ODS 与 T-1 回刷任务；用 adgroup_id + stat_time_day 对账 API 原始返回。
P0SPU / PID / 素材缺少效果归因事实现有 GMV Max 日报落表键为 Campaign；视频-SPU、Session-SPU 是关系快照。SPU、PID、素材 Tab 的成本、收入、订单、ROI 及排行。先与 TikTok 确认报表可用维度；若无对象级报表，页面应只展示关系/覆盖，不展示伪造的对象级广告效果。
P0内部商品 PID 与 TikTok spu_id 的语义未确认营销 ODS 中关联字段为 spu_id，业务 PID 看板要求 PID 主键；两者不能默认等同。PID Tab、SPU/PID 销售库存联动、素材归属。建立带 store_id、生效时间的商品映射；未命中时明确标注“待映射”。
P1素材授权生命周期已接入，等待生产联调identity/video/info 已补内部代理、具体 DTO 与 ODS 回刷；BI 从最新视频和身份 ODS 读取调用键，保留授权状态、起止时间、请求 ID 与完整响应 JSON。接口可用性不是卡点。素材 Tab 的可用数、过期数、风险动作。以 advertiser_id + identity_type + identity_id + item_id 回连；按 auth_end_time 建立生效/失效状态历史。行动点任务仍不采集。
P1时区、数据延迟与完整性门禁账户存在 timezone 与 display_timezone；报表与快照回流延迟不同。所有日级比较、T-1 展示、经营结论与异常识别。统一业务日口径，记录采集批次/水位；区分 0 行、全 0、延迟、失败，未通过时阻断结论。
P1项目跨币种与异常诊断依赖内部规则报告币种、汇率、高花费零单、探索状态、诊断标签、行动点均非 TikTok 单一 API 字段。项目总览的跨店汇总、预警与行动闭环。单独建设汇率/规则/行动任务数据集，保留规则版本与样本门槛。
P2接口分页、历史回刷、临时 URLCampaign 列表有大量记录；视频预览/封面 URL 有签名时效；日事实需要回刷修正。全量覆盖、历史趋势、素材预览稳定性。采集任务实现分页、幂等覆盖和近 7 日回刷；素材资产存稳定 ID，不把临时 URL 当永久地址。

七、接入顺序与验收

  1. P0：补齐 VSA 三段 API ODS。普通 Campaign、普通 Ad Group、Ad Group 日报；完成 VSA 判定、日级消耗回连、GMV Max/VSA 分类汇总对账。
  2. P0：冻结对象映射与粒度边界。确认 store_id + spu_id 到业务 PID/SPU 的映射；在对象级效果事实缺失时，禁止将 Campaign 聚合指标下摊。
  3. P1：扩展 GMV Max 报表与素材授权数据。基于真实接口能力补结构化指标/维度，并接入素材可用、过期、拒绝等主数据。
  4. P1：建设数据质量与规则层。统一时区、回刷、水位、完整性状态；将诊断、汇率和行动对象沉淀为可追溯数据集。
  5. P2：建设面向看板的 DWS/ADS。在 ODS 完整、粒度验证后，再按项目、Campaign、SPU、PID、素材分别聚合，避免前端跨多张 ODS 实时拼接。
最小验收集：（1）任一广告账户的 Campaign 快照条数可与上游分页总数核对；（2）VSA 由 Ad Group 判定，UNKNOWN 不进入 VSA 消耗；（3）VSA 日消耗可按 adgroup_id + stat_time_day 回连上游；（4）Campaign 日成本、收入、订单与 GMV Max 报表一致；（5）SPU/PID/素材无法归因时只输出关联关系与数据限制，不输出分摊指标。
