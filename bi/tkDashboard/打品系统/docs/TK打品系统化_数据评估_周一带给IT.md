## 0. 一句话背景（给 IT 快速对齐）

我们要把「运营凭经验决定下一步做什么」变成**系统自动生成、按风险排序、派单给运营的 TO-DO 工作台**。
方法：建一个**规则库**（16 条，见配套 xlsx），每条规则 = `触发条件（系统算）→ 责任人 → 标准动作 → 优先级 → 时限`。
今天讨论的核心：**我们现有数据够不够支撑这些规则的触发条件？缺的字段在哪些模块补？**

数据缺口集中在两类（大部分原始数据应已存在，要补的是「判断」）：
- **派生指标（计算类）**：要算出来的，如「库存可支撑天数」「日销环比」「老素材恢复率」。
- **状态/标记（判断类）**：要给结论的，如「生命周期阶段」「是否推品失败」「备货方向」。

## 2. 四个高成本「数据设计判断」（重点和 IT 敲定）

**① 生命周期阶段怎么自动判 —— 系统枢纽**
一堆规则 gate 在它上面，别纯人工打标，建议规则自动推：
- 新品 = 上架 ≤14 天 且 无放量渠道
- 测试 = 有投放/挂车，但仅在剪辑侧
- 放量 = 已进商务/直播渠道 或 日销持续增长
- 成熟 = 日销稳定高位 ≥N 天
- 衰退 = 日销连续下滑 ≥K 天
> 和 IT 确认：这套推导逻辑能不能落成一个定时 job / 视图？

**② 基线快照必须提前存，事后补不回来 —— 最紧急**
「老素材恢复率」要比「断货前均流量」，「日销环比」要比历史。
若现在只存当前值/不留历史，**断货那一刻的基线就永远丢了**。
> 第一优先级不是算指标，是先把 **日销、素材流量、库存 按天落历史表**。

**③ 口径必须锁死 —— 否则乱触发**
「库存可支撑天数」分母用近7日还是近3日均销？ROI 用哪个窗口、含不含自然流量？
> 上线前把每个派生指标写死成**唯一定义**，避免同规则在不同品上乱触发。

**④ 有些判断要「事件流」不是「累计快照」**
如 R-A1「到货后一周无投放」，需要的是「到货日之后有没有投放事件」，不是累计投放金额。
> 挂车、投放这类底层最好留**带时间戳的事件记录**，窗口判断从事件流算。

## 3. 建议搭建顺序（有依赖，不能跳）

1. **采集 + 历史留存层（地基）**：日销逐日、库存分仓、投放/挂车事件流、素材流量逐日。缺了上面全算不了。
2. **计算层**：派生指标（库存可支撑天数、均值/环比、ROI、海外仓占比、恢复率）做成定时 job，口径锁死。
3. **标记/规划层**：生命周期自动推导、协同节点结构化、失败标签工作流。依赖前两层产出。

> 可先用**已有数据就能算的规则**（断货预警 R-B2、备货触发 R-B1、爆量低备货 R-D2）把工作台跑起来，边跑边补。

## 4. 周一现场要问 IT 的问题清单

**A. 数据模块盘点**
- [ ] 现在系统分几块表（商品/订单/库存/广告/达人/素材…）？各存了什么？有字段清单/表头吗？

**B. 历史 vs 快照（决定基线能否重建，最重要）**
- [ ] 日销：按天留了历史，还是只有当前/累计？
- [ ] 库存：分仓存（本地/海外/在途），还是只有一个总量？
- [ ] 素材流量、广告花费：有逐日历史吗？
- [ ] 挂车/投放：存的是累计数，还是带时间戳的事件记录？

**C. 判断/状态字段**
- [ ] 生命周期阶段、季节属性、备货状态、失败标签：系统里有 / 人工在表格标 / 压根没有？

**D. 协同/规划**
- [ ] 达人寄样进度、月度推品计划、跨部门节点：在系统里 / 群里 / 在线表格 / 个人脑子里？

**E. 取数链路**
- [ ] 有数据库/BI/中台能直接查，还是主要靠导 Excel？
- [ ] **我们做过 BI 报表或数据看板吗？**（做过=底层查询链路通，重点放补判断字段；靠人工导表=先排「哪些必须先入库留历史」）
