## 0. 背景

- 上传材料：《产品推广与备货规划讨论》智能纪要（2026-07-17，李思唯主持），业务为**跨境服饰类 TikTok Shop（TK）**。
- 纪要已沉淀出一套相当完整的「打品 SOP」：月度规划四模块、单品全链路节点校验（到货/放量/备货/协同）、日常动态迭代、重点单品跟进（6675/6678/0575/0169）。
- **用户核心诉求**：打品思路已成型，且已自建 TK 运营系统、有大量数据；但「TO-DO（下一步做什么）」仍高度依赖运营个人经验。希望从**管理层面让这套节奏可复制化**，稳定复制给每一个运营。

## 1. 核心诊断

### 1.1 缺的是一层「规则 / 触发层」
链路现状：

```
数据层(已有·TK系统) → 信号层 → 规则/触发层(核心缺口) → 待办输出(自动派单)
                                        ↑___________ 反馈·调阈值 __________|
```

- 底层有数据（日销、ROI、库存、素材表现、到货状态……），顶层是运营每天的 TO-DO。
- 中间「从看到数据 → 知道该做什么」这一跳，目前靠运营脑子完成，没沉淀进系统 → 换经验浅的运营节奏就散。
- 把这一跳固化成系统里的**规则库**，即实现可复制。

### 1.2 「运营经验」其实在同时干三件事，只有一件难替代
1. **监测**：知道盯哪个指标、多久看一次 → **完全可自动化**（系统主动推信号）。
2. **研判**：看到信号判断真伪与原因 → 一半可固化成清单（如「异常波动先查库存/广告预算」），一半是真判断。
3. **决策**：选动作 + 排优先级 → **大部分已在纪要里**，只是还在人脑没进系统。

结论：真正非经验不可的只集中在「研判的一部分 + 边缘个例」。前后两件现在就能系统化。

### 1.3 纪要里的经验，其实已经是规则（含明确阈值）
- 到货后 1 周无挂车/投放 → 断档
- 日销稳定 15–20 单、仅浅测 → 启动备货测算
- 连续一周正向 → 启动放量筹备
- 库存深度需支撑 ≥ 1 个月 → 才能放量
- 秋冬款 → 测算 FBT，海外仓占比目标 90%
- 跨部门协同节点 → 提前 3 天校验进度

统一改写为格式：**触发条件（系统算）→ 责任人 → 标准动作(TO-DO) → 优先级 → 时限**，即为规则库。

- **队列按风险排序**：P0（断货/断档/协同卡点等不可逆损失）永远置顶，新运营无需判断先做哪件。

- 顶部 KPI：P0 待办数 / 今日新增 / 逾期。
- 侧栏「重点跟进」= **手动锁定**单品（6675/6678/0575/0169），给「经验判断」留人工口子，不全靠规则。

## 4. 落地提醒（重要）

1. **阈值必须与运营主管逐条确认**：文件里填的是纪要默认值。尤其「日销触发区间」「目标ROI」不同品类差别大，填错会漏报或天天误报。
2. **别一次全铺**：先上 3–5 条最救命的 P0（断货预警 R-B2、备货触发 R-B1、协同卡点 R-C1），跑两周调准阈值、建立运营信任，再加 P1/P2。告警太密→运营无视→系统废掉。
3. **重点跟进留人工口子**：像 6675/6678 需要人盯的，不该全自动化。目标是「把经验用在刀刃上」，不是 100% 自动化。
4. **反馈回路是关键**：每周复盘规则命中率、哪个阈值太松/太紧，持续调参 → 经验沉淀进规则库而非个人。
