一、需求背景

当前打品动作较多依赖运营经验判断，下一步希望沉淀为“系统自动生成、按风险排序、派单给运营的 TO-DO 工作台”。系统通过规则库判断单品、素材、库存、投放、达人协同等状态，自动生成责任人、标准动作、优先级和处理时限。

本需求文档聚焦数据落地评估：现有数据是否足够支撑 16 条规则触发，缺失字段应补在哪些业务模块，哪些指标需要先建立历史留存和统一口径。

二、目标与范围

2.1 建设目标

  • 建立规则触发所需的数据字段、派生指标和状态标记清单。
  • 确认哪些规则可基于现有数据先上线，哪些需要补字段或新建模块。
  • 为后续规则引擎、派单工作台和运营 TO-DO 看板提供数据依据。

2.2 本期边界

  • 本期先做数据侧可行性评估，不直接定义最终页面交互。
  • 规则动作、负责人、优先级以配套规则表为准，本页只整理数据依赖。
  • “现状”列需在 IT 盘点后补齐，当前默认待确认。

三、数据缺口总览

数据缺口主要集中在两类。第一类是派生指标，例如库存可支撑天数、日销环比、老素材恢复率；这类指标通常依赖历史明细和统一计算口径。第二类是状态或标记，例如生命周期阶段、是否推品失败、备货方向；这类字段看似简单，但往往需要系统自动判断、人工回写和工作流配合。

优先级建议：先补“按天历史留存”和“事件流时间戳”，再做派生指标。否则部分基线数据事后无法补回，规则会缺少可靠触发依据。

五、高成本数据设计判断

5.1 生命周期阶段自动判定

生命周期阶段是多条规则的触发枢纽，不建议完全依赖人工打标。可与 IT 确认是否落为定时任务或数据视图。

新品上架不超过 14 天，且无放量渠道。
测试已有投放或挂车，但主要在剪辑侧验证。
放量已进入商务 / 直播渠道，或日销持续增长。
成熟日销稳定高位持续达到 N 天。
衰退日销连续下滑达到 K 天。

5.2 基线快照必须提前保存

老素材恢复率需要对比断货前均流量，日销环比需要对比历史。如果当前只存现值或累计值，断货时点的基线无法事后补回。

第一优先级不是立即计算所有指标，而是先把日销、素材流量、库存按天落历史表。

5.3 派生指标口径必须唯一

库存可支撑天数的分母使用近 7 日均销还是近 3 日均销，ROI 使用哪个投放窗口、是否包含自然流量，都需要在上线前锁定唯一口径。否则同一条规则在不同商品上可能出现不一致触发。

5.4 窗口判断需要事件流

例如 R-A1“到货后一周无投放”，需要判断到货日之后是否发生投放事件，而不是读取累计投放金额。挂车、投放等底层数据建议保留带时间戳的事件记录，再由事件流计算窗口判断。

六、建议搭建顺序

  1. 采集 + 历史留存层：先补日销逐日、库存分仓、投放 / 挂车事件流、素材流量逐日。该层是后续规则计算的地基。
  2. 计算层：将库存可支撑天数、均值 / 环比、ROI、海外仓占比、恢复率等派生指标做成定时任务，并锁定口径。
  3. 标记 / 规划层：补生命周期自动推导、协同节点结构化、失败标签工作流等能力。该层依赖前两层产出。
MVP 建议：优先选择现有数据较可能支撑的规则启动工作台，例如断货预警 R-B2、备货触发 R-B1、爆量低备货 R-D2，边运行边补齐判断字段。

七、周一 IT 调研问题清单

7.1 数据模块盘点

  • 现在系统分几块表或数据模块，例如商品、订单、库存、广告、达人、素材？各模块是否有字段清单或表头？

7.2 历史与快照

  • 日销是按天留历史，还是只有当前值或累计值？
  • 库存是否按本地、海外、在途分仓保存，还是只有一个总库存？
  • 素材流量、广告花费是否有逐日历史？
  • 挂车、投放存的是累计数，还是带时间戳的事件记录？

7.3 判断与状态字段

  • 生命周期阶段、季节属性、备货状态、失败标签目前在系统里已有、人工表格维护，还是完全没有？

7.4 协同与规划

  • 达人寄样进度、月度推品计划、跨部门节点目前沉淀在系统、群消息、在线表格，还是个人经验中？

7.5 取数链路

  • 当前能否从数据库、BI 或中台直接取数，还是主要依赖人工导出 Excel？
  • 是否已经做过 BI 报表或数据看板？如果做过，说明底层查询链路可能已具备，后续重点转向补判断字段和历史留存。

八、讨论后输出物

  • 补齐模块缺口表的“现状”列，标记已有直接可用、有但要改造、没有需新建。
  • 将 16 条规则重排为：现有数据即可上线、需补字段后上线、需新建模块后上线。
  • 形成开发 / 埋点排期清单，标注优先级、数据来源、依赖模块和责任方。
  • 沉淀规则引擎数据结构，例如规则 JSON schema 与触发伪代码骨架。
