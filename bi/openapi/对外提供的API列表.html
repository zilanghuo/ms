一、文档目的

本文用于沉淀需要提供给外部服务商使用的 API 列表、接入边界、鉴权要求和数据责任口径。当前先形成接口清单 HTML 草稿，后续接口字段、请求示例和错误码可继续在本文件中补齐。

当前约定：外部服务商不直接访问 TikTok Shop API、积加 ERP Open API 或底层 Supabase 数据库，统一通过 IT API 网关访问内容中台开放接口。

二、接入边界

  • 数据来源：内容中台已同步和维护的数据，包括 TikTok Shop API 自动同步数据、积加 ERP API 自动同步数据、运营人工维护数据。
  • 访问方式：外部服务商通过 HTTPS 调用 IT API 网关，由网关完成鉴权、审计、限流和权限控制。
  • 数据范围：默认只开放服务商业务所需的只读查询接口；涉及新增、修改、删除类接口需单独评审。
  • 字段口径：接口入参和出参使用 camelCase，底层表字段或内部字段仍按数仓规范使用小写下划线。

三、API 接口清单

以下为拟开放给外部服务商使用的 API 清单。接口路径、鉴权方式、请求字段和返回字段在服务商范围确认后继续细化。

序号 接口名称 接口路径 方法 接口用途 使用的业务模块 数据来源 备注
1 TK店铺列表 /openapi/tiktok/content/stores GET 查询可用于商品列表和商品详情入参的 TK 店铺列表。 tk商品维护 复用 TK 看板店铺选项：tk/options/stores 无业务入参；返回 storeName 和 siteCode。
2 商品列表查询 /openapi/tiktok/content/products POST 按店铺、商品状态、创建时间、审核状态等条件分页查询内容中台商品基础资料。 tk商品维护 DWD 表：dwd.dwd_product_tiktok_product_detail_df 请求体为 JSON；pageSize 最大 100；列表 SKU 不返回库存明细。
3 商品详情查询 /openapi/tiktok/content/product/detail POST 根据商品 ID 和店铺名称查询单个商品详情，详情 SKU 返回库存明细。 tk商品维护 DWD 表：dwd.dwd_product_tiktok_product_detail_df；SKU、库存等来自 ODS 子表 请求体传入 productId + shopName。
4 SKU详情关系（积加） /openapi/jijia/product/sku/spu/detail POST 查询积加 SKU 与 SPU 产品关系，支持按 SKU 或 SPU 精确筛选。 tk商品维护 ODS 表：ods.ods_product_api_jijia_sku_spu_detail_df sku 和 spu 均可不传；productId 不作为入参。
5 TK产品状态列表 /openapi/tiktok/content/product/status/list GET 查询 TK 商品可用状态枚举，供外部服务商筛选或展示。 tk商品维护 DIM 表：dim.dim_product_tiktok_product_enum_df（enum_type=product_status） 查询同一张枚举维表，按 enum_type 区分。
6 TK产品审核状态列表 /openapi/tiktok/content/product/audit/status/list GET 查询 TK 商品审核状态枚举，供外部服务商筛选或展示。 tk商品维护 DIM 表：dim.dim_product_tiktok_product_enum_df（enum_type=audit_status） 查询同一张枚举维表，按 enum_type 区分。

  • 对外接口字段统一使用 camelCase，例如 createTimeGe、createTimeLe、auditStatus。

3.3 SKU详情关系（积加）

模块一：对外参数说明（外部服务商使用）

该接口面向外部服务商提供积加产品台账中的 SKU 与 SPU 关系查询能力。接口只沉淀对外模块信息，请求参数和响应字段统一使用 camelCase；底层来源参考 MySQL 表 business_ledger_product。

对外入参数

参数位置参数类型必填示例说明
Bodyskustring否Color-Red-XM01SKU；可不传，传入时按 SKU 精确查询。

BodypageNumnumber是1页码，从 1 开始。

sku 和 spu 可以同时不传；都不传时按最新分区分页返回数据。

四、通用接入要求

4.1 鉴权与安全

  • 所有接口必须通过 HTTPS 访问，不允许明文 HTTP。
  • 外部服务商通过 API Key / App Secret / 签名方式接入，具体方案由 IT API 网关统一实现。
  • 所有请求需记录调用方、接口路径、请求时间、响应状态、耗时和 traceId，便于审计与问题追踪。
  • 原则上只开放最小必要字段，不直接暴露 TikTok Shop、积加 ERP 或数据库内部敏感字段。

4.2 通用请求头

Header必填说明
Authorization是服务商访问凭证或签名结果，具体格式待网关方案确认。
X-App-Id是服务商应用 ID，用于识别调用方。
X-Timestamp是请求时间戳，用于防重放。
X-Trace-Id否调用链追踪 ID；未传时由网关生成。
