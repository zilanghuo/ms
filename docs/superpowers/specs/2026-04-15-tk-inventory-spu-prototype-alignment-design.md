# TK库存检查 SPU原型统一化设计

## 背景

当前库存检查模块已有原型页 `bi/tkDashboard/库存检查/htmls/TK库存检查-PID&SKU看板.html`，页面中包含 `PID&SKU维度` 与 `SPU维度` 两个 tab。

现状问题：

- `PID&SKU维度` 已按完整业务字段展示库存检查主表。
- `SPU维度` 在原型语义上仍停留在“建议按明细基础聚合生成”的占位状态，没有完全体现与 `PID&SKU维度` 相同的业务字段结构。
- 业务预期已明确：`SPU维度` 原型应与 `PID&SKU维度` 基本一致，仅主维度不同。

## 目标

将 `SPU维度` 原型调整为 `PID&SKU维度` 的同构聚合版，满足以下要求：

- 页面布局、筛选区、汇总区、字段分组、仓别字段、异常口径说明与 `PID&SKU维度` 保持一致。
- `SPU维度` 仅保留 `SPU / SPU名称` 作为主维度展示字段。
- `PID / SKU / SKU名称` 不在 `SPU维度` 明细表中展示。
- 其余业务字段继续展示，保持与 `PID&SKU维度` 同一套库存检查视图。

## 设计方案

### 1. 页面结构

保留现有单页面双 tab 结构，不新增独立 HTML 页面。

- 查询区继续共用同一套筛选条件。
- 顶部 tab 继续使用 `PID&SKU维度` 与 `SPU维度` 两个视图切换。
- 两个视图使用相同的页面样式、按钮、说明区、汇总卡片和表格风格。

### 2. SPU视图展示原则

`SPU维度` 使用与 `PID&SKU维度` 一致的展示骨架，仅做以下差异化处理：

- 主维度列保留：`时间`、`店铺`、`SPU`、`SPU名称`
- 主维度列移除：`PID`、`SKU`、`SKU名称`
- 采购、国内、三方、FBT、海外、汇总、仓明细等业务字段全部保留
- `库存是否异常` 在 `SPU` 聚合结果基础上重新判断，不直接复用明细结果

### 3. 汇总卡片

`SPU维度` 汇总卡片沿用与 `PID&SKU维度` 相同的数量和结构，仅调整文案：

- `SKU总数` 改为 `SPU总数`
- `异常SKU数` 改为 `异常SPU数`
- 其余如 `总库存`、`总可用库存`、`总在途库存` 保持一致

### 4. 文案调整

需移除现有 `SPU维度` 仍处于建议态的文案，替换为确定性描述：

- 明确 `SPU维度` 基于 `PID&SKU` 底表按 `SPU` 聚合生成
- 明确除主维度差异外，其余业务字段与 `PID&SKU维度` 保持一致
- 明确异常口径以 `SPU` 聚合后的库存差异重算

## 不做事项

本次仅调整原型表达，不扩展以下内容：

- 不新增后端接口设计
- 不新增独立 SPU 页面文件
- 不修改需求文档中的核心业务口径
- 不对现有筛选器做结构性改造

## 验收标准

- `SPU维度` 原型在视觉结构上与 `PID&SKU维度` 保持一致
- `SPU维度` 不再出现“建议后续生成”类占位描述
- `SPU维度` 明细表仅去掉 `PID / SKU / SKU名称` 三列，其余业务字段完整保留
- `SPU维度` 汇总卡片文案与主维度匹配
- 用户可直接将两个 tab 视为同一看板的两个粒度视图
