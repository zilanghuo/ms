# tkDashboard index 三层导航设计

## 背景

当前 `bi/tkDashboard/index.html` 左侧导航使用两层结构：

- 一级为栏目标题
- 二级为具体原型页面链接

现业务需求要求将业务栏目调整为三层结构，在栏目与具体原型之间增加一层“版本号”。

## 目标

将 `index.html` 中的业务栏目导航调整为三层结构：

- 一级：业务栏目
- 二级：版本号
- 三级：具体原型页面

同时保留以下栏目现状，不参与本次改造：

- 技术文档
- 源数据集成列表

## 设计方案

### 1. 改造范围

仅改动 `bi/tkDashboard/index.html`：

- 更新左侧导航的 HTML 结构
- 增加三层导航需要的样式
- 保持现有 iframe 切页逻辑不变

不新增独立脚本文件，不抽离导航配置。

### 2. 导航层级规则

业务栏目采用以下结构：

- 一级：栏目名称，例如 `销售数据&pid`、`库存模块`
- 二级：版本节点，例如 `销售数据&pid 1.0`、`库存模块 1.0`
- 三级：具体原型，例如 `店铺统计`、`商品统计`、`PID数据看板`、`库存检查看板`

版本号层本次仅作为结构分组层，不增加折叠、展开、点击跳转等新交互。

### 3. 保持不变的部分

以下栏目保持当前结构和样式逻辑，不调整为三层：

- `销售数据&pid(技术文档)`
- `源数据集成列表`

### 4. 样式表达

三层结构通过缩进、字号和颜色区分层级：

- 一级栏目继续沿用当前 `.nav-group-title`
- 二级版本号使用弱一级但强于三级的分组样式
- 三级原型链接继续复用 `.nav-item`，但增加额外缩进

不引入折叠箭头、计数徽标或复杂状态样式。

### 5. 交互规则

- 只有第三级原型链接可点击
- 点击行为保持现有逻辑：更新 iframe、标题、breadcrumb、active 状态
- 第二级版本号仅做分组标题，不参与点击

## 验收标准

- `销售数据&pid`、`库存模块` 等业务栏目已改成三层
- 具体原型位于版本号节点之下
- `技术文档` 和 `源数据集成列表` 保持现状
- 原有 iframe 切换和 active 高亮逻辑可继续使用
