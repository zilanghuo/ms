# 三店照片详情导出设计

## 目标

让照片详情导出脚本可在一次命令中按既有日期或日期范围，依次处理三家紫鸟店铺；每店导出“已绑定账号”和“联盟账号”两份 Excel，上传既有接口，并在该店处理结束后关闭浏览器窗口。

## 店铺配置

脚本内置且按下列顺序执行：

| 文件名前缀 | 紫鸟店铺名称 |
| --- | --- |
| 1店 | 美国TK-艾斯特尼-美区跨境1店 |
| 3店 | 美国TK-艾斯特尼-美区跨境3店（原大魔王） |
| 英国直邮店 | 美国TK-艾斯特尼-英国直邮店 |

店铺名称仅用于从紫鸟返回的店铺列表中唯一匹配；前缀只用于生成归档文件名。

## 命令行与流程

新增 `--all-shops`。启用后，脚本逐店执行下列流程：

1. 解析店铺 ID，启动该店紫鸟窗口并连接 Selenium。
2. 对 `--date` 或 `--start-date` 至 `--end-date` 的每一个日期，导出“已绑定账号”和“联盟账号”。
3. 生成 `<店铺前缀>-<账号类型>-YYYYMMDD.xlsx`；同名文件仅在新文件完整下载后原子覆盖。
4. 将每份 Excel 以现有 `file` multipart 参数上传至既有接口，除非传入 `--skip-upload`。
5. 无论该店成功或失败，均断开 Selenium 并调用 `stopBrowser`；随后才开始下一店。

未传 `--all-shops` 时，保留 `--browser-id`、`--browser-name` 与 `--shop-label` 的单店行为。`--all-shops` 不可与 `--browser-id`、`--browser-name`、`--shop-label` 组合，避免目标和文件名前缀不明确。

## 错误处理与验证

- 若任一内置店铺无法唯一匹配，抛出包含店铺名称的错误，不会误选其他店。
- 单店关闭逻辑使用 `finally`，确保出错后不会遗留该店窗口。
- 单元测试覆盖内置店铺清单、文件名前缀以及参数互斥；保留现有日期、下载和上传响应测试。
